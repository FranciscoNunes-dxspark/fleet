# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

What a production build ships and what it weighs, in the terminal: each file raw, gzip and brotli, the modules and packages inside it (from esbuild's metafile, rollup-plugin-visualizer's data for Vite and Rollup, webpack's stats, or the output folder and its source maps), the packages bundled twice, the change against the last build or main's, budgets, and `ballast check`, `ballast compare` and `ballast security` for a pipeline. Ballast is a keyboard-driven terminal app built with Ink (React for the terminal) on Node 22+, a sibling of Splice, Trawl, Sonar, Bosun, Hail, Keel, Wharf, Locker, Mooring, Bilge and Chart. Plain JavaScript ES modules with `.jsx` for components; no TypeScript, no linter config. The README is the user-facing spec; when behaviour changes, update it too.

It lives in the fleet repository, in `apps/ballast`, and is built on the fleet's shared kit, `@fleet/kit` (`packages/kit`; the root CLAUDE.md has its rules). Import the kit's files as `@fleet/kit/<file>`; Ballast keeps no copy of any of them, never imports Bilge's (the advisories and licences come from the kit's `osv.js` and `lockfiles.js`, which Bilge reads too), and a change to a kit file is a change to every app, so run every app's tests (`npm test` at the root). `src/app.js` tells the kit which app this is (`configureApp`: the name `ballast`, the title `Ballast`, the version a build bakes in); import `VERSION` and `COMPILED` from it. `src/theme.js` fills the kit's `theme` object with Ballast's palette (copper).

## Commands

```bash
npm install                                                    # once, at the repository root: every app and the kit
npm test                                                       # whole suite (node:test), here; npm run test:ballast at the root
node --import @fleet/kit/register.js --import ./src/app.js --test test/stats.test.js       # one file
node --import @fleet/kit/register.js --import ./src/app.js --test --test-name-pattern="webpack" test/*.test.js   # tests matching a name
npm start                                                      # run from the checkout on this folder (needs a real TTY)
npm run demo                                                   # run against the in-memory demo project (needs a real TTY)
node bin/ballast.js check --demo                               # the headless check, on the demo
npm run build                                                  # Bun-compiled executable for this machine → dist/ (the kit's scripts/build.js)
node scripts/logo.js                                           # regenerate assets/ from src/pet.js
```

`--import @fleet/kit/register.js` is required whenever Node loads `.jsx`. The tests also preload `--import ./src/app.js`, so the kit knows the app before any test file loads. CI runs Ballast's tests on Linux and Windows whenever `apps/ballast` or the kit changes, so paths must work on both (a file's and a module's path are always `/`-separated). Nothing in the suite reaches the network or runs npm, git, a bundler or anything else: the demo and fake `run`s stand in.

Releases are automatic, as every app's: a push to main that changes `apps/ballast` (or the kit, `patches/` or the root package files) releases it as `ballast-v<version>` (root CLAUDE.md, "Releases"). Compiled builds get the version via `process.env.BALLAST_VERSION`.

## Architecture

- **The provider** (`src/provider.js`): everything Ballast reads and runs goes through one object, `createBallast({ run, home, fetchImpl, now, temp })`: `read(dir, { stats, outDirs })`, `budgets(dir)`, `plan(dir)` and `build(dir, plan)`, `git(dir)` (`{ commit, branch, dirty }` or null), `resolveRef(dir, ref)`, `buildRef(dir, commit, { progress })`, `runs(root)` and `saveRun(root, summary)`, `advisories([{ name, version }])` (Map `name@version` → advisories), `security(dir)`, `writeFile`. `src/demo.js` `demoBallast({ noStats, mainSaved, budgets })` has the same interface for `--demo` and the tests (`state.calls`, `state.runs`, `state.written`); a new operation needs both, and its test. Commands run through the kit's `run.js` (the provider's `run`, faked in tests). **Everything put in a command line is checked**: a ref by `safeRef`, a path by `safePath` (buildplan.js); keep that for any new command. `build` runs a plan and removes its temporary folder whatever happened; `buildRef` adds a detached git worktree, installs (`installCommand`), plans, builds, and removes the worktree in a `finally`.
- **Stats** (`src/stats.js`, pure): `detectFormat`, `statsJson` (a JSON file, or the visualizer's data inside its HTML), `parseEsbuild`, `parseVisualizer` (from `nodeMetas` → `moduleParts` → `nodeParts.renderedLength`, so a module in two chunks is in both), `parseWebpack` (chunks → files, a concatenated module's `modules` opened up, a stylesheet's modules to the chunk's `.css`, orphans and maps out, `children` merged), `cleanId`. A parsed build is `{ tool, chunks: [{ name, bytes, modules: [{ id, bytes }], entry }], outputPath? }`.
- **Packages** (`src/packages.js`, pure): `packageOf(path)` → `{ name, installPath, version? }` from the last `node_modules/` (scoped names, npm's nested copies, pnpm's `.pnpm/<name>@<version>`, Yarn's cache), `parentOf`, `compareVersions`, `majorOf`, `safePackageName`. **Source maps** (`src/sourcemap.js`, pure): `decodeSegment` (VLQ), `sourceSizes(map, code)` (characters per source, `[unmapped]` for the rest; index maps not read), `mapUrlOf`.
- **The build** (`src/build.js`, pure): `finishChunk` makes a chunk `{ file, name, raw, gzip, brotli, kind, entry, modules: [{ id, bytes, pkg }] }`, modules scaled to the file's raw size and given their package and version (`versionAt(installPath)`); `stableName` (the file without its content hash, what matches one build's chunk with another's), `kindOf`, `totals`, `moduleSize` (a module's share at its chunk's ratio, an estimate), `packageTotals`. `src/modules.js`: `moduleTree` (packages grouped, installs as children when more than one, own files by folder with single-folder chains joined), `treeRows`, `duplicates` (`versions` or `paths`, `wasted` all but the biggest copy). `src/sizes.js`: `compressedSizes` (node:zlib), `parseSize`, `formatBytes` (kB is 1000), `formatDelta`, `formatPercent`, `sizeIn`.
- **The disk** (`src/disk.js`, reads only): `readBuild(root, { statsPath, outDirs })` (a stats file, the newest of `findStatsFiles`, its chunks found on the disk by `locate` and sized there; else each file of the output folders, `OUTPUT_DIRS`, with its source map's modules), `readLock` (package-lock.json here or up to three folders above: version by install path, licence through the kit's `parseNpmLock`, else the installed package.json), `readBudgetsFile` (ballast.json, else package.json's `fleet.ballast`), `readSecurity`, `projectFiles`. **How to build with stats** (`src/buildplan.js`, pure): `buildPlan({ pkg, files, temp })` (Vite with `--sourcemap --outDir <temp>` read as `dist`, webpack `--json`, a plain esbuild script with `--metafile`, else the build script), `installCommand`, `safeRef`, `safePath`.
- **Comparing** (`src/compare.js`, pure): `summarize(build, { commit, branch, dirty })` is what's kept of a build (`key` the commit, `+dirty` with changes); `compareRuns(base, head, measure)` → `{ measure, total, chunks, packages, headline, reason }` (`commonMeasure` falls back to raw); `packageReason` says why a package changed ("now imported whole": three times the modules, ten at least); `compareMarkdown` the pull request's table; `runLabel`. `src/history.js`: `<home>/runs/<name>-<hash>.json`, newest first, one per key (`saveRun`, `loadRuns`, `lastRun`, `runAt`). `src/base.js` `savedBase(provider, root, { base, key })` → `{ run, name }` or `{ missing, canBuild? }`, which the app (asking first) and `--build` follow with `buildRef`.
- **Budgets** (`src/budgets.js`, pure): `readBudgets(json)` (`errors` for what doesn't read), `parseBudget`, `parseFailOn` (`budget`, `growth>N%`, `growth>NkB`, `none`), `globToRegExp`, `checkBudgets(chunks, budgets, measure)` (each matching file held to the limit, `total` over all, `none` for a glob matching nothing, never a failure), `growthFails`, `budgetLine`, `growthLine`.
- **Security** (`src/security.js`, pure; findings in the kit's `findings.js` shape): `bundleSecrets(path, text)` runs the kit's `codescan.js` secret rules (`SECRET_RULES`) over a built file, a long minified line cut into `pieces` codescan reads (≤ 2000 characters) and the finding put back at the file's line, one a rule a line; **the excerpt is redacted by codescan and never leaves it whole**, and `securityJson` leaves it out of `--json`. `mapFinding(folder, maps)`: one `source-map` finding a folder, medium with `sourcesContent`, low without. `sarifOf` (the kit's `toSarif`). `ballast security --json` is the kit's `securityJson` and Fleet reads it: keep its shape.
- **`src/headless.js`**: `HEADLESS`, `parseArgs`, `runHeadless(args, { provider, config, write })` resolves the exit code (0, 1 failing, 2 couldn't run), which `cli.jsx` runs before asking for a terminal. `check` and `compare` keep the build they read (`saveRun`) before looking for the base; nothing is built without `--build`; `--base-stats` reads a base from a stats file.
- **`src/actions.js`**: every user-facing operation, written once; keys and slash commands call these with `ctx`. The questions before a build (`buildOnce`) and a worktree build (`compare`) live here. `read` and `buildOnce` go through `took` (git, the summary saved, the budgets read) and then `compare(…, { quiet: true })`, which only uses what's kept.
- **`src/commands.js`**, **`src/help.js`**: the slash-command table and completion; the `?` window's sections.
- **`src/ui/App.jsx`**: as Bilge's (its CLAUDE.md), with `data` `{ build, git, summary, budgets }` and **`ctx`** getters `measure` (the setting, else the budgets file's, else gzip), `checks` (the budgets against the build, worked out in `derive` only when the build, the budgets or the measure change), `compare` (`{ base, name, run?, result?, missing? }`), `security`, `advisories` (a Map for the session); `compareBase()`/`setCompareBase`, `setCompare`, `setSecurity`, `showModules(file)`. It reads the build on opening; nothing polls. `ctx.refresh` (ctrl+r) is `read`.
- **`src/ui/*View.jsx`**: Chunks, Modules, Duplicates, Compare, Log. Views must check `ctx.viewHasKeys()` at the start of their `useInput` handlers; `useListNav` from the kit is the cursor (Compare's headers aren't `selectable`). `Viewer.jsx` shows text over the view, with the kit's search.
- **The family** (`@fleet/kit/family.js`, shared and never edited here; `src/moods.js`, pure): Ballast is in `FAMILY` (role `BUNDLE`, Plod). `t` hands Splice a `file` context (a module of the project's own); `w` copies `/why <package>` for Bilge with `copiedNote` (Bilge takes no package context: don't invent a kind). It takes no context (`/take` says whose). Reads, builds and `/security` go to the activity log with the folder: sizes and counts only, never anything from inside the bundle. Plod's mood to `writeMood`; tests point `FAMILY_HOME` at a temp folder (`tempHome`). `/env` is the kit's `environments.js`; `submit` calls `recordCommand('ballast', line)`.
- **Config** (`src/config.js`): `~/.ballast/config.json`, overridable with `BALLAST_HOME` (the runs are under it too). Change it only through `ctx.setConfig`.
- **Updates, hosted mode, mouse, theme and text**: as Wharf's (its CLAUDE.md): `appTerminal()` in `cli.jsx`, the update only in compiled builds and never hosted, `useMouse` in views, colours read from `theme` while drawing, `@fleet/kit/text.js` for widths.
- **Plod** (`src/pet.js`, `src/ui/Pet.jsx`): the tortoise's pixel art and mood. `assets/` is generated from it by `scripts/logo.js` (the "KB" badge); don't hand-edit those files.

## Tests

`test/app.test.js` and `test/family.test.js` are end-to-end: `<App>` over `demoBallast()` with `ink-testing-library`, typing keys and asserting on `lastFrame()` and `provider.state`. `test/stats.test.js` covers the parsers over `test/fixtures/` (an esbuild metafile with code splitting, a Vite build's visualizer data with pnpm paths, webpack 5's stats with a concatenated module, CSS and a nested lodash), packages from paths, hashes, source maps and the module tree; `test/disk.test.js` the provider over temporary folders (an output folder and its maps, stats found and sized from the files, the lock file, budgets files, the security read, the build and the worktree build through a fake `run`); `test/compare.test.js` summaries, reasons, the Markdown, the runs kept, the base, sizes and budgets; `test/headless.test.js` `ballast check`, `compare` and `security` over the demo and a folder. A test file that writes a key builds it from pieces and starts with `// bilge-ignore-file`. Use `until(check, what)` to wait for frames rather than fixed sleeps.

## Keeping things in sync

Adding or changing a key or command touches several places: the handler (view or `App.jsx`), `src/commands.js` for slash commands, the `?` window's sections in `src/help.js`, the footer `HINTS` in `App.jsx`, and the tables in `README.md`. Commit messages are short sentences describing the change, without type prefixes.
