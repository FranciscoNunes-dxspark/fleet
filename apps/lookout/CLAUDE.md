# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

A local HTTP and HTTPS proxy in the terminal: what a browser, an emulator or a project's own server sends and receives, recorded live, shown with headers, bodies (the kit's DataViewer) and timings, filtered, exported to and imported from HAR, and handed to Hail as a request in a `.http` file (`h`). HTTPS is a tunnel recorded by host name until interception is on; then Lookout answers with certificates from a CA of its own, made once in `~/.lookout`. `lookout security`, `lookout ca` and `lookout env` run headless. Lookout is a keyboard-driven terminal app built with Ink (React for the terminal) on Node 22+, a sibling of Splice, Trawl, Sonar, Bosun, Hail, Keel, Wharf, Locker, Mooring, Bilge and Chart. Plain JavaScript ES modules with `.jsx` for components; no TypeScript, no linter config. The README is the user-facing spec; when behaviour changes, update it too.

It lives in the fleet repository, in `apps/lookout`, and is built on the fleet's shared kit, `@fleet/kit` (`packages/kit`; the root CLAUDE.md has its rules). Import the kit's files as `@fleet/kit/<file>`; Lookout keeps no copy of any of them, and a change to one is a change to every app, so run every app's tests (`npm test` at the root). `src/app.js` tells the kit which app this is (`configureApp`: the name `lookout`, the title `Lookout`, the version a build bakes in); import `VERSION` and `COMPILED` from it. `src/theme.js` fills the kit's `theme` object with Lookout's palette (sand, `#f4a259`). Lookout draws in the kit's shell look (`look: 'shell'` in `src/app.js`, the kit's `look.js`): the top line (`topLine`: Peep's face, the views with their counts, `headerContext` at the right, most needed first since what doesn't fit is left off), the view, the activity, a one-row prompt, and the status line (`StatusLine`: what Peep says, the keys); the welcome is the status line's message until the first command.

## Commands

```bash
npm install                                                    # once, at the repository root: every app and the kit
npm test                                                       # whole suite (node:test), here; npm run test:lookout at the root
node --import @fleet/kit/register.js --import ./src/app.js --test test/proxy.test.js   # one file
node --import @fleet/kit/register.js --import ./src/app.js --test --test-name-pattern="refused" test/*.test.js   # tests matching a name
npm start                                                      # listen on 127.0.0.1:8888 (needs a real TTY)
npm run demo                                                   # a made-up session (needs a real TTY)
node bin/lookout.js security --demo                            # the headless check, on the demo
npm run build                                                  # Bun-compiled executable for this machine → dist/ (the kit's scripts/build.js)
node scripts/logo.js                                           # regenerate assets/ from src/pet.js
```

The tests preload `--import ./src/app.js` and need `--import @fleet/kit/register.js` for `.jsx`. Nothing in the suite leaves the machine: the proxy's tests start origin servers on 127.0.0.1 (HTTPS with a certificate of a test CA, `origins()` in `test/helpers.js`) and the proxy on port 0, and every home folder is temporary (`tempHome`: `LOOKOUT_HOME` and `FAMILY_HOME`). CI runs them on Linux and Windows.

Releases are automatic, as every app's (root CLAUDE.md, "Releases"): `lookout-v<version>`, the version from `process.env.LOOKOUT_VERSION` in compiled builds.

## Architecture

- **The proxy** (`src/proxy.js`): `createProxy({ certs, intercept, passThrough, maxBody, upstreamCa, onExchange })` → `{ listen(port), close(), configure(next), address }`, on `127.0.0.1` only; never listen anywhere else. A plain request (absolute URL) is forwarded with node:http/https (keep-alive agents, hop-by-hop headers dropped, `headerObject`), bodies streamed with `tap` keeping `maxBody` bytes. A CONNECT is answered 200, then its first bytes decide: not TLS, a host on the pass-through list (`matchesHost`, `*.example.com`), interception off or a name no certificate can carry → `tunnel` (bytes each way); else `interceptTls`: a server-side `tls.TLSSocket` with the host's context, ALPN `http/1.1` only, over `replayed(client)` (a Duplex that gives back the peeked bytes: Bun's TLSSocket misses an `unshift`), emitted into an inner `http.Server` whose requests are forwarded as `https`. A TLS error before any request, or a close within 1.5 s with no request, is a `refused` exchange with the reason (`refusalReason`: HTTP/2 only, the certificate turned down). Upgrades (WebSocket) pass as bytes after their handshake is recorded. Requests for the proxy itself (origin-form, or `http://lookout/`) get a short page and `/ca.crt`. `configure({ paused })` keeps forwarding and records nothing.
- **Exchanges** (`src/exchange.js`, pure): the shape (`{ id, kind: 'http'|'tunnel'|'refused', state, at, scheme, method, host, port, path, url, intercepted, request, response, timings, note, error }`, headers as `[name, value]` pairs in their order and case, bodies as Buffers), `decoded` (gzip, deflate, br undone), `bodyText`, `isData`, the filter (`parseFilter`, `matches`, `filtered`: host:, status:, method:, words searched in masked text), `hosts`, `capturedLine` (the activity log's only words). The proxy hands the same object on each change; App keeps them in a ref (5000 at most), numbers them (`id`) and draws at most every 100 ms.
- **Certificates** (`src/asn1.js`, `src/certs.js`, `src/store.js`): a DER encoder and X.509 v3 by hand (no dependency): `makeCA` (EC P-256, basicConstraints CA:true pathLen 0, keyUsage keyCertSign/cRLSign, ten years), `issue(host, ca, leafKey)` (subjectAltName DNS or IP, serverAuth, AKI/SKI, a year), signed with `crypto.sign`. `store.js`: `~/.lookout` (`lookoutHome`, `LOOKOUT_HOME`), `ensureCA` writes `ca-key.pem` 0600 in a 0700 folder (off Windows) and `ca.crt`; `certCache(ca)` one leaf key per run and a secure context per host, kept. **The CA key never leaves `~/.lookout`**: nothing serves, copies, logs or exports it.
- **Redaction** (`src/redact.js`, pure): what's a credential (`isSecretHeader`, `isSecretParam`, and `secretsIn` — the kit's `codescan.js` secret rules, applied to any text) and the masks (`maskHeader` keeps a scheme and cookie names, `maskUrl`, `maskBody` for JSON and forms, `maskText` with the kit's `redact` and family.js's `redactSecrets`). **Every place traffic is shown, searched, exported or handed on goes through these** (detail, rows, filter, HAR without `secrets`, findings); keep that for anything new. `detail.js` builds the detail view's text (`secrets` only when `s` asked, and never kept).
- **To Hail** (`src/httpfile.js`, pure): `requestWithVariables` puts `{{variables}}` in place of every credential (Authorization keeps its scheme, `{{cookie}}`, `{{apiKey}}`, query and body fields by name, codescan's finds), `httpBlock` is a block of a `.http` file in Hail's shape (`### …`, a `# from Lookout at …` comment, `# @name` unique against `namesIn`), `requestContext` the family's `request` context with the same variables. `actions.hail` writes the file (`lookout.http`, `httpFile`) through the provider and copies `/open <file>` with `copiedNote('hail', …)`; `t` copies `/take` of the context.
- **HAR** (`src/har.js`, pure): `toHar(list, { secrets })` (masked unless `secrets`, which `/export … secrets` asks before), `fromHar(text)` (imported exchanges, `imported: true`).
- **Security** (`src/security.js`, pure): `trafficFindings(list)` in the kit's findings shape (`token-over-http`, `cookie-over-http`, `secret-in-body-over-http`, `credentials-in-query`, `cookie-not-secure`, `cookie-not-httponly`; a step milder to localhost), one per rule, place and title with a `count`, `where` without the query, never a value; cached per finished exchange. App saves the session's `securityJson` to `~/.lookout/findings.json` (findings only, never traffic) two seconds after they change; `lookout security` reads that, a HAR file, or the demo (`src/headless.js`, `HEADLESS`, `runHeadless`). Keep its JSON shape: Fleet adds it up.
- **Setup** (`src/setup.js`, pure): `proxyLines`, `bosunEnv` (bosun.json's `"env"`), `httpsProxyLine`, `trustSteps(certPath, { platform })` (this system first, then Firefox, Node, curl, Python, Android, then the others).
- **The provider** (`src/provider.js`): `createLookout({ home, upstreamCa })`: `start`, `stop`, `configure`, `address`, `caInfo` (cached 2 s), `ensureCA`, `readFile`, `exists`, `writeFile`, `saveFindings`, `loadFindings`. `src/demo.js` `demoLookout()` has the same interface (`state.calls`, `state.written`, `emit(ex)`, start hands over `demoExchanges()`); a new operation needs both, and its test.
- **`src/actions.js`**: every user-facing operation, written once; keys and slash commands call these with `ctx`. The questions (making the CA, passing a host through, clearing, exporting credentials, replacing a file) live here.
- **`src/commands.js`**, **`src/help.js`**: the slash-command table and completion; the `?` window's sections.
- **`src/ui/App.jsx`**: layout, focus, the prompt, overlays (`help`, `detail`, `data` with `back`, text) and **`ctx`** (read the `Object.assign(ctx, {...})` block before adding an action): `exchanges()`, `shown()`, `selected()`, `onExchange`, `listening`, `paused`, `filter`, `setListening`, `setPaused`, `setFilter`, `clearExchanges`, `addExchanges`, `takeUnlogged`, `task`, `note`, `confirm`, `copy`, `showText`, `showDetail`, `showData`, `setView`, `port` (`--port`). It listens on opening unless `autoStart` is false; unmounting flushes the activity line and stops the proxy.
- **`src/ui/*View.jsx`**: Requests (follows new rows on the last one), Hosts, Security, Setup (a `Viewer` as a view: `search={false}`, `passKeys`), Detail (over `Viewer`, `passKeys` s d r h t p), Log. Views check `ctx.viewHasKeys()` first; `useListNav` from the kit is the cursor.
- **The family** (`@fleet/kit/family.js`, shared and never edited here): Lookout is in `FAMILY` (role `PROXY`, Peep). It hands Hail `/open <file>` and `request` contexts and takes none (`/take` says whose). **Nothing captured goes into a context unmasked, a mood or the activity log**: moods carry counts and the port (`src/moods.js`), the activity log `capturedLine`'s counts and host names (`flushActivity`: on /stop, /clear, quitting, every five minutes). `/env` is the kit's `environments.js`; `submit` calls `recordCommand('lookout', line)`.
- **Config** (`src/config.js`): `~/.lookout/config.json` (`LOOKOUT_HOME`): `port`, `autoStart`, `intercept`, `passThrough`, `maxBodyMb`, `httpFile`, and the family's usual ones. Change it only through `ctx.setConfig`.
- **Updates, hosted mode, mouse, theme and text**: as Bilge's: `appTerminal()` in `cli.jsx`, the update only in compiled builds and never hosted, `useMouse` in views, colours read from `theme` while drawing.
- **Peep** (`src/pet.js`, `src/ui/Pet.jsx`): the meerkat's pixel art and mood. `assets/` is generated by `scripts/logo.js`; don't hand-edit those files.

## Tests

`test/proxy.test.js` the proxy between real clients and origin servers (plain HTTP through an absolute URL, a CONNECT tunnel, an intercepted handshake trusting the generated CA through `tunnelAgent`, refused and HTTP/2-only handshakes, pass-through, pausing, a 502, the self page, 127.0.0.1); `test/certs.test.js` the DER encoder, the CA and leaves through `X509Certificate`, a real TLS handshake, the CA's file permissions; `test/traffic.test.js` redaction everywhere (masks, detail, `.http` blocks, the request context, HAR), the HAR round trip, the filter, the activity line and the security rules; `test/headless.test.js` `lookout security`, `ca` and `env`; `test/app.test.js` end to end over the demo with `ink-testing-library` (and once over the real proxy), asserting on frames, `provider.state`, the clipboard and the family's files. Use `until(check, what)` and `eventually` rather than fixed sleeps.

## Keeping things in sync

Adding or changing a key or command touches the handler (view or `App.jsx`), `src/commands.js`, `src/help.js`, `HINTS` in `App.jsx`, and the README's tables. Commit messages are short sentences describing the change, without type prefixes.
