# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Helm is a PowerShell script editor in the terminal, like the ISE: two views (Script: the script over the console; Console: the console full height, with the keys) over one interactive PowerShell with a terminal of its own. Keyboard-driven, built with Ink on Node 22+, plain JavaScript ES modules with `.jsx` for components. The README is the user-facing spec; when behaviour changes, update it too. It lives in `apps/helm` and uses the shared kit (`@fleet/kit`; the root CLAUDE.md has its rules); `src/app.js` tells the kit the app's name, and `src/theme.js` fills the kit's theme. Helm draws in the kit's shell look (`look: 'shell'` in `src/app.js`, the kit's `look.js`): the top line (`topLine`: the name, and `headerContext` at the right: the file, `*` while unsaved, the PowerShell), the views' tabs, the panes, a one-row prompt (while a path or a find is asked, its rows taken from the script) and the status line (`StatusLine`: the keys, or what a path prompt asks for).

## Commands

```bash
npm test                      # here; npm run test:helm at the root
npm start                     # needs a real TTY
node --import @fleet/kit/register.js --import ./src/app.js --test test/buffer.test.js   # one file
```

## Architecture

- **`src/powershell.js`**: `locate()` finds `pwsh`, else `powershell` on Windows.
- **`src/terminal.js`**: the console, as Mooring's `terminal.js` is a server's shell. `openTerminal({ bin, cwd, columns, rows, onChange, onPrompt, onExit })` returns `{ vt, write, resize, close, alive, marks }`: PowerShell (`shellArgs`: `-NoLogo -NoExit -EncodedCommand SETUP`) with a terminal of its own, its output through the kit's `VirtualTerminal` (5000 lines of scrollback), `write` the keys as they came. No native module (Fleet's Bun builds can't carry one), so `launchFor` picks: on Linux util-linux `script -qfec <sh command> /dev/null`, on macOS BSD `script -q /dev/null /bin/sh -c …` (SHELL is /bin/sh for script, the user's put back before PowerShell starts); the sh command sets the size with `stty`, reports `tty` as OSC 5380 and execs PowerShell; a resize is `stty -F`/`-f` on that tty (`sttyArgs`) once the size has settled. On Windows a relay: PowerShell compiling `RELAY_SOURCE` (C# 5, for Windows PowerShell's compiler) with Add-Type, once, into `%TEMP%\helm-pty-<hash>-<edition>.dll` (in memory when that fails), which opens a pseudo console (`STARTF_USESTDHANDLES` with none, so the program doesn't get the relay's pipes), runs `HELM_PTY_COMMAND` in it and copies bytes both ways; a resize is `ESC ] 5381 ; cols ; rows BEL` on its input (taken out there; typed text can't carry one), and its input ending closes the pseudo console. `SETUP` wraps the `prompt` function to print `ESC ] 5381 ; 1|0 BEL` (0 when `$?` was false or `$Error[0]` changed) first; `outputReader` takes the OSC 5380/5381 marks out (a mark cut between chunks waits) and answers the terminal questions PowerShell asks on Unix (`CSI 6n` with the cursor where it was asked, `5n`, `c`), which the kit's `VirtualTerminal` doesn't. `marks` stays false where an older pseudo console drops the marks: App then doesn't wait for a run's end.
- **`src/buffer.js`** (pure): the script text as `{ lines, row, col, anchor? }` (`anchor` is where a selection began), every edit returning a new one; selection, `extend`, `find`. **`src/help.js`**: what F1 lists. **`src/highlight.js`** (pure): colours one line, puts the cursor in it, scrolls it sideways.
- **`src/ui/App.jsx`**: the screen and all keys. It takes `shell` (`{ name, open(options) }`: cli.jsx's openTerminal for the PowerShell found, or null) and opens it at the console pane's size, telling it each new size (the Console view is taller). Ink doesn't report function keys (F5 arrives as an empty key), so `useKeyTranslation` turns F5 and F8 into ctrl+r and ctrl+e; in the Console view it hands every key to the shell instead, as it came, but `CONSOLE_KEYS` (F5, F8, ctrl+t and ctrl+\ back to the script, ctrl+q, shift+PgUp/PgDn looking back), so Ink sees none. F5 types `. '<file>'` (the saved file when it has no changes, else a copy in `scratch`, a temporary folder removed at exit; `psQuote`), F8 the line, or several selected lines as `scratch/selection.ps1`; with `marks` a run is `running` until the prompt's mark (`finishRun`), which sets Spoke's mood and the activity line. esc and ctrl+c send ctrl+c (only while a run is under way, unless there are no marks). Messages (saved, opened, not found) are a note in the status line for 5 s. Undo is a stack of buffers (edits within 500 ms share a step). The text, prompt, focus and path mode live in refs updated synchronously as well as in state: keys can arrive faster than React renders.
- **Mouse**: `cli.jsx` takes `terminalMouse` and hands it to App as `mouse`; App maps clicks, drags (`claimDrags`, so the app selects for itself) and the wheel onto the layout it drew (`geo`: the top line is row 0, a pane's title row is next, the code starts at column `2 + GUTTER`).
- **The family** (`@fleet/kit/family.js`): Helm is in `FAMILY`, `ROLES` (PS), `APP_NAMES` and `PET_NAMES` (Spoke, a ship's cat). `src/pet.js` is only the one-line `FACES` and `moodFor` (running: looking; a run that failed or was stopped: worried for 8 s; one that went well: happy for 4 s); `src/moods.js` is `familyMood` and `reactionTo` (a worried, sad or happy sibling, one line in the status line until esc). App writes its mood, polls `readMoods` every `moodEvery` ms and logs each run to the activity log as *which script* (`Ran a.ps1`, `Ran a selection`, `Ran a command`), and whether it failed: never the code, the output or an error's words. `family={false}` (every test but the family one) keeps it out of `~/.family`. Helm has no slash prompt, so Fleet's proposals (`PROMPT_APPS`) leave it out. Fleet hosts Helm (`i`).

## Tests

`test/app.test.js` renders `<App>` over a fake shell (`fakeShell`: a `VirtualTerminal`, what was typed, `say`, `prompt(ok)` for a mark, `end`) with `ink-testing-library`, typing keys and asserting on frames and on what reached the shell (wait with `until`, never fixed sleeps, except to let typed text settle before a key that reads it). `test/terminal.test.js` has `launchFor` and `outputReader`, `sh` through the real `script` (Linux and macOS), the relay running Windows PowerShell (Windows only: CI's windows-latest is where it runs), and real PowerShell where it's installed (CI's runners have pwsh; skipped without one; on Windows the marks are checked only if they come through).
