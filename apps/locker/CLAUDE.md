# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Secrets and configuration in the terminal: a project's `.env` files, `appsettings*.json`, .NET user secrets and Hail's env files side by side with an App Service app's settings and a key vault, by key, what is missing and what differs (compared by hash, never shown unless asked), Key Vault references checked, and what is about to expire. Locker is a keyboard-driven terminal app built with Ink (React for the terminal) on Node 22+, a sibling of Splice, Trawl, Sonar, Bosun, Hail, Keel and Wharf. Plain JavaScript ES modules with `.jsx` for components; no TypeScript, no linter config. The README is the user-facing spec; when behaviour changes, update it too.

It lives in the fleet repository, in `apps/locker`, and is built on the fleet's shared kit, `@fleet/kit` (`packages/kit`; the root CLAUDE.md has its rules). Import the kit's files as `@fleet/kit/<file>`; Locker keeps no copy of any of them, and a change to one is a change to every app, so run every app's tests (`npm test` at the root). Anything only Locker needs lives in its own file (`drift.js`, `clipguard.js`). `src/app.js` tells the kit which app this is (`configureApp`: the name `locker`, the title `Locker`, the version a build bakes in); import `VERSION` and `COMPILED` from it. `src/theme.js` fills the kit's `theme` object with Locker's palette (brass).

## Commands

```bash
npm install                                                    # once, at the repository root: every app and the kit
npm test                                                       # whole suite (node:test), here; npm run test:locker at the root
node --import @fleet/kit/register.js --import ./src/app.js --test test/drift.test.js      # one file
node --import @fleet/kit/register.js --import ./src/app.js --test --test-name-pattern="Vault view" test/*.test.js   # tests matching a name
npm start                                                      # run from the checkout, in a project's folder (needs a real TTY)
npm run demo                                                   # the demo project and Azure (needs a real TTY)
npm run build                                                  # Bun-compiled executable for this machine → dist/ (the kit's scripts/build.js)
node scripts/logo.js                                           # regenerate assets/ from src/pet.js
```

`--import @fleet/kit/register.js` is required whenever Node loads `.jsx`: it installs a module hook (the kit's `jsx-hooks.js`) that compiles `.jsx` with esbuild on import. There is no dev build step. The tests also preload `--import ./src/app.js`, so the kit knows the app before any test file loads. CI runs Locker's tests on Linux and Windows whenever `apps/locker` or the kit changes, so path handling and line endings must work on both (`.gitattributes` forces LF). Nothing in the suite reaches Azure or the clipboard.

Releases are automatic, as every app's: a push to main that changes `apps/locker` (or the kit, `patches/` or the root package files; not Markdown-only ones) releases it as `locker-v<version>` (root CLAUDE.md, "Releases"). Compiled builds get the version via `process.env.LOCKER_VERSION`.

## Values

The rule everything here keeps: **a value never goes anywhere but the screen on an explicit reveal (`v`), the clipboard through the guard (`y`), or the file it was asked into (`a`)**. Not into a note, a task's output (`ctx.task`'s `stdout` and `/last`), an error, the activity log (`task`'s `activity` names the secret and where, never what), a mood, a context for a sibling, or the settings file. The drift matrix compares values by `drift.js` `fingerprint`, an HMAC under a key made once per run, and keeps only group letters (`A`, `B`), never the hashes. A revealed value lives only in its overlay (`ctx.showText(..., { secret: true })`), whose `y` copies through the guard. Tests check the family's folder for the demo's values (`noValues` in `test/app.test.js`): keep that for anything new.

## Architecture

- **The provider** (`src/azure/arm.js`): everything Azure goes through `createAzure({ fetch, token })`: `subscriptions`, `sites` and `slots` (App Service, function apps included), `settings`, `connectionStrings`, `references` (ARM's configreferences), `vaults`, and each vault's own API with a token of its own: `secrets` and `certificates` (listed without values; the secrets behind certificates left out), `secretValue` (the only read of a value), `setSecret`, `enableSecret`, `portalUrl`. A secret's name is checked before it reaches an address (`secretPath`). `src/demo.js` `demoAzure()` has the same interface for `--demo` and the tests, with `state.calls` (never a value); a new operation needs both, and a test against `fakeFetch` in `test/azure.test.js`.
- **`src/azure/az.js`**: tokens from `az account get-access-token`, cached until five minutes before they run out, as Sonar's; `az login` is the only sign-in, and `azProblem` says sign-in trouble in those words.
- **The folder** (`src/local.js`): `readLocal(dir)` and `createLocal({ dir })` (`sources()`, `addToEnv(file, key, value)`, the only write), with the pure parsers: `parseDotenv`, `addToDotenv` / `dotenvValue` (what is written reads back the same), `flatten` (appsettings as .NET reads them), `userSecretsId` / `userSecretsPath`. A source is `{ id, kind, label, file, entries: [{ key, value }], writable, example?, problem? }`. `demo.js` `demoLocal()` is its demo (`state.files`, `state.calls`).
- **`src/keys.js`**: pure. `normKey` (one setting whatever the spelling: `:`, `__`, `--`, any case), `vaultName` / `isVaultName`, and Key Vault references (`isReference`, `parseReference` for both `SecretUri=` and `VaultName=;SecretName=`, `referenceText`).
- **`src/drift.js`**: pure (but for the run's HMAC key). `driftMatrix(columns, { vaults })`: a row per key with a cell per column (`missing`, `value` + `group`, `ref`, `broken`, `present`), `checkReference` (the vault's listing first, then App Service's own status), `filterRows` (`all`, `diff`, `missing`), `driftCounts`, `cellMark`. A vault secret a reference names sits in the referring row. A vault column's missing cells don't make a row missing.
- **`src/load.js`**: what is read and how it becomes columns: `loadSubscription` (apps with their slots, six at a time, and vaults), `loadTarget`, `loadVault`, `pickTarget` (saved, the only app, or the one named as the folder), `referencedVaults`, `appEntries` (connection strings as `ConnectionStrings:<name>`), `driftColumns` (the `columns` setting; Hail's env files hidden by default), `vaultMap`.
- **`src/expiry.js`**: pure. `expiring` (soonest first), `expiryWords`, `shortExpiry`, `expiryTone`, `expiryNotice` (the start-up line and notification).
- **`src/clipguard.js`**: `clipGuard({ copy, read, after })`: `put(value)` copies and empties the clipboard after `clearClipboard` seconds if it still holds the value (or can't be read back); `flush()` does it now, which `cli.jsx` awaits on every way out. App takes it as the `guard` prop; tests pass a recorder.
- **`src/actions.js`**: every user-facing operation, written once. Keys and slash commands call these with `ctx`. Everything that changes something or moves a value asks first (`ctx.confirm`; `danger` for a new version and for disabling); a new value is typed through `ctx.askSecret` (masked).
- **`src/commands.js`**: the slash-command table (`name`, `args`, `desc`, optional `complete`, `run(ctx, rest)`) and completion; your own commands (`usercommands.js`) come after them.
- **`src/ui/App.jsx`**: layout, focus, the prompt, overlays (help, palette, `Picker.jsx`, `Viewer.jsx`), the activity lines and **`ctx`** (read the `Object.assign(ctx, {...})` block before adding an action): `data` (getter: what was read and `derive`'s columns, `matrix`, `expiringItems`, `trouble`), `config`, `task` (a visible, cancellable job; `reload: { local }` or `{ vault }` reads that again after), `note`, `confirm`, `askText`, `askSecret`, `copy` (plain text), `copySecret` (through the guard), `showText`, `showPicker` / `refreshPicker`, `chooseTarget` / `chooseVault` / `chooseSubscription`, `setFilter`, `cursor` (where a view's cursor was, so an overlay doesn't lose it). It reads the folder and Azure on opening, each part on its own so one failing leaves the rest (the header says why); there is no polling, `ctrl+r` reads again. Uppercase shortcuts are alt+letter (`shortcutKey`), your keys (`keymap.js`) and `ctrl+p` go through `useKeyTranslation`.
- **`src/ui/*View.jsx`**: one component per tab: Drift (the app's and vault's columns pinned at the right, the folder's scrolling), Vault, Expiry, Sources, Log. Views check `ctx.viewHasKeys()` first in their `useInput` handlers and act on `nav.current()` (the row as of the last key), not the row last drawn.
- **The family** (`@fleet/kit/family.js`, shared; `src/share.js`, `src/moods.js`, pure): Locker is in `FAMILY` and takes `site` contexts (an App Service app or slot: `siteIn` finds it by id, or name, slot and group). `t` copies `/appsettings <app>` for Sonar through `copiedNote` (which tells Fleet). `/family` (`familyChoices`, with the app for Sonar), `/wiring` and `/timeline` are the siblings'. Hush's mood goes to `writeMood` when it changes and the siblings' are read every `moodEvery` ms (`reactionTo`); `familyMoods: false` turns both off; tests point `FAMILY_HOME` at a temp folder (`tempHome`). Sonar copies a `site` for Locker with `alt+k` on an app in Resources (`/locker`).
- **Config** (`src/config.js`): `~/.locker/config.json`, overridable with `LOCKER_HOME` (tests use it); `expiryDays` and `clearAfter` read their settings with the defaults. Change it only through `ctx.setConfig`: `App` saves its whole copy (and tells `onConfig`, which the guard reads).
- **Updates** (`@fleet/kit/update.js`): once a day, the newest `locker-v…` release; only in compiled builds, and off inside Fleet (`appTerminal()`'s `hosted`).
- **Hosted mode**: `cli.jsx` takes its streams from `appTerminal()` and gives them to its TTY check, `terminalMouse` and Ink's `render`, and draws on the alternate screen; it writes nothing else to the real terminal but the expiry notification's bell. `apps/fleet/CLAUDE.md` has the protocol; Fleet hosts Locker as its eighth space (`alt+8`, `ctrl+] l`).
- **Mouse** (`@fleet/kit/mouse.js`): as the siblings'; views register with `useMouse(ctx, handler)`, a view's rows start one line under its panel's top border (two in Drift, under its header row).
- **Theme and text**: a dark and a light palette in `src/theme.js`; every colour is read from `theme` while drawing; `@fleet/kit/text.js` (`fit`, `wrap`, `stringWidth`) for width-aware truncation, never `.length`.
- **Hush** (`src/pet.js`, `src/ui/Pet.jsx`): the octopus's pixel art and mood (`moodFor`, from `troubles`: expiring, broken, drift). `assets/` is generated from it by `scripts/logo.js`; don't hand-edit those files.

## Tests

`test/app.test.js` and `test/family.test.js` are end-to-end: they render `<App>` over `demoAzure()` and `demoLocal()` with `ink-testing-library`, type keys into stdin and assert on `lastFrame()`, on the demos' state and on the family's folder (no value in it). `test/azure.test.js` covers the ARM and Key Vault client against a fake fetch, the az sign-in and the clipboard guard; `test/drift.test.js` the keys, references, the matrix, the columns and expiry; `test/local.test.js` the folder's parsers and a real temp folder. Use `until(check, what)` from `test/helpers.js` to wait for frames rather than fixed sleeps.

## Keeping things in sync

Adding or changing a key or command touches several places: the handler (view or `App.jsx`), `src/commands.js` for slash commands, the `?` window's sections in `src/help.js`, the footer `HINTS` in `App.jsx`, and the tables in `README.md`. Commit messages are short sentences describing the change, without type prefixes.
