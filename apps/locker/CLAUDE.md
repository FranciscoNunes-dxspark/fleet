# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Secrets and configuration in the terminal: a project's `.env` files, `appsettings*.json`, .NET user secrets and Hail's env files side by side with an App Service app's settings and a key vault, by key, what is missing and what differs (compared by hash, never shown unless asked), Key Vault references checked, and what is about to expire. Locker is a keyboard-driven terminal app built with Ink (React for the terminal) on Node 22+, a sibling of Splice, Trawl, Sonar, Bosun, Hail, Keel and Wharf. Plain JavaScript ES modules with `.jsx` for components; no TypeScript, no linter config. The README is the user-facing spec; when behaviour changes, update it too.

It lives in the fleet repository, in `apps/locker`, and is built on the fleet's shared kit, `@fleet/kit` (`packages/kit`; the root CLAUDE.md has its rules). Import the kit's files as `@fleet/kit/<file>`; Locker keeps no copy of any of them, and a change to one is a change to every app, so run every app's tests (`npm test` at the root). Anything only Locker needs lives in its own file (`drift.js`, `clipguard.js`). `src/app.js` tells the kit which app this is (`configureApp`: the name `locker`, the title `Locker`, the version a build bakes in); import `VERSION` and `COMPILED` from it. `src/theme.js` fills the kit's `theme` object with Locker's palette (brass).

Locker draws in the kit's shell look (`look: 'shell'` in `src/app.js`, the kit's `look.js`): the top line (`topLine`: Hush's face, the views, with their digits from 120 columns, and `headerContext` at the right, most telling first, as the line drops parts from its end), the view, the activity, a one-row prompt, and the status line (`StatusLine`: a flash, a sibling's news, what went wrong reading Azure, the welcome until the first command, else Hush's mood; then the keys).

## Commands

```bash
npm install                                                    # once, at the repository root: every app and the kit
npm test                                                       # whole suite (node:test), here; npm run test:locker at the root
node --import @fleet/kit/register.js --import ./src/app.js --test test/drift.test.js      # one file
node --import @fleet/kit/register.js --import ./src/app.js --test --test-name-pattern="Vault view" test/*.test.js   # tests matching a name
npm start                                                      # run from the checkout, in a project's folder (needs a real TTY)
npm run demo                                                   # the demo project and Azure (needs a real TTY)
npm run build                                                  # Bun-compiled executable for this machine → dist/ (the kit's scripts/build.js)
node scripts/logo.js                                           # regenerate assets/ from src/pet.js
```

`--import @fleet/kit/register.js` is required whenever Node loads `.jsx`: it installs a module hook (the kit's `jsx-hooks.js`) that compiles `.jsx` with esbuild on import. There is no dev build step. The tests also preload `--import ./src/app.js`, so the kit knows the app before any test file loads. CI runs Locker's tests on Linux and Windows whenever `apps/locker` or the kit changes, so path handling and line endings must work on both (`.gitattributes` forces LF). Nothing in the suite reaches Azure or the clipboard.

Releases are automatic, as every app's: a push to main that changes `apps/locker` (or the kit, `patches/` or the root package files; not Markdown-only ones) releases it as `locker-v<version>` (root CLAUDE.md, "Releases"). Compiled builds get the version via `process.env.LOCKER_VERSION`.

## Values

The rule everything here keeps: **a value never goes anywhere but the screen on an explicit reveal (`v`), the clipboard through the guard (`y`), or the file it was asked into (`a`)**. Not into a note, a task's output (`ctx.task`'s `stdout` and `/last`), an error, the activity log (`task`'s `activity` names the secret and where, never what), a mood, a context for a sibling, or the settings file. The drift matrix compares values by `drift.js` `fingerprint`, an HMAC under a key made once per run, and keeps only group letters (`A`, `B`), never the hashes. A revealed value lives only in its overlay (`ctx.showText(..., { secret: true })`), whose `y` copies through the guard. Tests check the family's folder for the demo's values (`noValues` in `test/app.test.js`): keep that for anything new.

## Architecture

- **The provider** (`src/azure/arm.js`): everything Azure goes through `createAzure({ fetch, token })`: `subscriptions`, `sites` and `slots` (App Service, function apps included), `settings`, `connectionStrings`, `references` (ARM's configreferences), `vaults`, and each vault's own API with a token of its own: `secrets` and `certificates` (listed without values; the secrets behind certificates left out), `secretValue` (the only read of a value), `setSecret` (`{ version }`, the new one's id), `versions` (a secret's, newest first), `enableSecret` (a version's with `{ version }`), `restart` (an app or slot, the ARM call `az webapp restart` makes), `probe` (a plain GET without a token: `{ status }`, never throwing but on a cancel), `portalUrl`. A site has `hostName` (its default address). A secret's name is checked before it reaches an address (`secretPath`). `src/demo.js` `demoAzure()` has the same interface for `--demo` and the tests, with `state.calls` (never a value), `state.versions` and `state.health` (the statuses a host's probes answer in turn); a new operation needs both, and a test against `fakeFetch` in `test/azure.test.js`.
- **`src/azure/az.js`**: tokens from `az account get-access-token`, cached until five minutes before they run out, as Sonar's; `az login` is the only sign-in, and `azProblem` says sign-in trouble in those words.
- **The folder** (`src/local.js`): `readLocal(dir)` and `createLocal({ dir })` (`sources()`, `tracked()` (git's files, or null), `text(file)`, `addToEnv(file, key, value)`, the only write), with the pure parsers: `parseDotenv`, `addToDotenv` / `dotenvValue` (what is written reads back the same), `flatten` (appsettings as .NET reads them), `userSecretsId` / `userSecretsPath`. A source is `{ id, kind, label, file, entries: [{ key, value }], writable, example?, problem? }`. `demo.js` `demoLocal()` is its demo (`state.files`, `state.calls`). `/move` (`actions.js` `move`, the kit's `folders.js`: `folderChoices` with `hasSettings`, `resolveFolder`) gives App's `moveTo` another folder: `makeLocal(dir)` (createLocal's; null in the demo) replaces the reader (`localRef`), `store.dir` is the folder (`ctx.cwd()`, the top line), the config's `projects` remembers it, and the app `pickTarget` names for it is chosen.
- **`src/keys.js`**: pure. `normKey` (one setting whatever the spelling: `:`, `__`, `--`, any case), `vaultName` / `isVaultName`, and Key Vault references (`isReference`, `parseReference` for both `SecretUri=` and `VaultName=;SecretName=`, `referenceText`).
- **`src/drift.js`**: pure (but for the run's HMAC key). `driftMatrix(columns, { vaults })`: a row per key with a cell per column (`missing`, `value` + `group`, `ref`, `broken`, `present`), `checkReference` (the vault's listing first, then App Service's own status), a row's `leak` (`{ prefix, what, reason, in }`: a `.env` column's browser variable holding a secret, judged by the kit's `codescan.js` `frontendLeak`; DriftView's `!`, `leakWords` for `↵`), `filterRows` (`all`, `diff`, `missing`), `driftCounts`, `cellMark`. A vault secret a reference names sits in the referring row. A vault column's missing cells don't make a row missing.
- **`src/load.js`**: what is read and how it becomes columns: `loadSubscription` (apps with their slots, six at a time, and vaults), `loadTarget`, `loadVault`, `pickTarget` (saved, the only app, or the one named as the folder), `referencedVaults`, `appEntries` (connection strings as `ConnectionStrings:<name>`), `driftColumns` (the `columns` setting; Hail's env files hidden by default), `vaultMap`, `environmentPicks`.
- **`src/expiry.js`**: pure. `expiring` (soonest first), `expiryWords`, `shortExpiry`, `expiryTone`, `expiryNotice` (the start-up line and notification).
- **`src/clipguard.js`**: `clipGuard({ copy, read, after })`: `put(value)` copies and empties the clipboard after `clearClipboard` seconds if it still holds the value (or can't be read back); `flush()` does it now, which `cli.jsx` awaits on every way out. App takes it as the `guard` prop; tests pass a recorder.
- **`src/actions.js`**: every user-facing operation, written once. Keys and slash commands call these with `ctx`. Everything that changes something or moves a value asks first (`ctx.confirm`; `danger` for a new version and for disabling); a new value is typed through `ctx.askSecret` (masked).
- **`src/rotate.js`**: `/rotate` and the Vault view's `r`, `rotateSecret(ctx, name)`: one checklist (a `ctx.showText` overlay with `follow`, shown again at every step, whose `onClose` cancels) and one `ctx.task` for everything after the value is chosen, with the questions asked inside it. Each step goes to `ctx.log` by name. Pure and exported: `newValue`, `referencesTo` (an app's references to a secret, `version` null for the latest), `healthUrl`, `waitHealthy`, `checklist`. The hand-off to Sonar (`copiedNote`) comes after the task, so Fleet doesn't switch away mid-rotation.
- **`src/leaks.js`**: `/leaks`. Pure and exported: `PATTERNS` (the shapes), `secretKeys` (the keys known to be secret: the kit's `isSecretName`, as `maskValue` decides), `findSecrets(line, known)`, `masked` / `maskedLine` (the kit's `maskValue` and `redactSecrets`; a finding keeps only these, never the value), `addedLines` (`git log -p --pretty=fuller --unified=0`, read without a `%` format, since `run.js` goes through `cmd.exe` on Windows), `parseSince`, `isExampleFile`. `scanRepo(root, { known, range, signal, onBatch })` lists the files with `git ls-files -co --exclude-standard`, then reads the history 25 commits at a time through `run.js`. `leaks(ctx, arg)` shows the picker again after each batch while it is the one on screen (`ctx.isShowing`), its `onClose` stopping the scan; `t` is Splice's `commit` or `file` context, `r` `rotateSecret` for a vault secret (`vaultSecretFor`).
- **`src/hygiene.js`**: pure, `/hygiene`'s and `locker security`'s judging, as the kit's findings (`findings.js`; `where` a vault's `kv/secret`, a setting's `site/key`, a file's path with `line`; Locker's own `scope`: `vault`, `app`, `file`). `vaultItemFindings` (expiry, no expiry, age, disabled but referenced; `vaultUse` says what the apps refer to and which certificates `WEBSITE_LOAD_CERTIFICATES` loads), `vaultPostureFindings` (from `vaultFrom`'s `posture`), `settingFindings` (plain-text secrets by name, `isSecretSetting`, or by the kit's codescan shapes, `secretShape`; a slot's reference against another's plain value), `localFindings` (secrets in files git tracks), `frontendFindings` (a `.env`'s browser variables holding a secret, `frontendLeak`, tracked or not), `sharedSecretFindings` (the same `fingerprint` in two environments, `envOfSource` / `envOfSite`), `hygieneFindings` (all of them, sorted). Judged from metadata and the shape of values already held, never from a vault secret's value; a finding's `excerpt` is `redact`ed.
- **`src/security.js`**: `readHygiene` (what the check reads: the folder with `tracked()` and `text()`, the app with its slots or every app with `all`, and their vaults' listings) and `/hygiene` (`hygiene(ctx, arg)`, a task then a picker: `↵`, `y` name, `f` fix, `s` in its view, `r` rotate). **`src/headless.js`**: `locker security` (`runSecurity`), from `cli.jsx` before the TTY check: text, `--json` (the kit's `securityJson`) or `--sarif`, exit 1 at `--fail-on`.
- **`src/commands.js`**: the slash-command table (`name`, `args`, `desc`, optional `complete`, `run(ctx, rest)`) and completion; your own commands (`usercommands.js`) come after them.
- **`src/ui/App.jsx`**: layout, focus, the prompt, overlays (help, palette, `Picker.jsx`, `Viewer.jsx`), the activity lines and **`ctx`** (read the `Object.assign(ctx, {...})` block before adding an action): `data` (getter: what was read and `derive`'s columns, `matrix`, `expiringItems`, `trouble`), `config`, `task` (a visible, cancellable job; `reload: { local }` or `{ vault }` reads that again after), `note`, `confirm`, `askText`, `askSecret`, `copy` (plain text), `copySecret` (through the guard), `cancel` (the running task), `log` (a line for the family's activity log, for a job of several steps), `showText` (with `onClose`, called when esc closes it, and `follow`, opened scrolled to the end), `showPicker` / `refreshPicker` / `isShowing` (whether a picker is the overlay on screen; a picker's `onClose` hears esc), `chooseTarget` / `chooseVault` / `chooseSubscription`, `setFilter`, `cursor` (where a view's cursor was, so an overlay doesn't lose it). It reads the folder and Azure on opening, each part on its own so one failing leaves the rest (the status line says why); there is no polling, `ctrl+r` reads again. Uppercase shortcuts are alt+letter (`shortcutKey`), your keys (`keymap.js`) and `ctrl+p` go through `useKeyTranslation`.
- **`src/ui/*View.jsx`**: one component per tab: Drift (the app's and vault's columns pinned at the right, the folder's scrolling), Vault, Expiry, Sources, Log. Views check `ctx.viewHasKeys()` first in their `useInput` handlers and act on `nav.current()` (the row as of the last key), not the row last drawn.
- **The family** (`@fleet/kit/family.js`, shared; `src/share.js`, `src/moods.js`, pure): Locker is in `FAMILY` and takes `site` contexts (an App Service app or slot: `siteIn` finds it by id, or name, slot and group). `t` copies `/appsettings <app>` for Sonar through `copiedNote` (which tells Fleet). `/family` (`familyChoices`, with the app for Sonar), `/wiring` and `/timeline` are the siblings'. Hush's mood goes to `writeMood` when it changes and the siblings' are read every `moodEvery` ms (`reactionTo`); `familyMoods: false` turns both off; tests point `FAMILY_HOME` at a temp folder (`tempHome`). Sonar copies a `site` for Locker with `alt+k` on an app in Resources (`/locker`).
- **Environments** (`@fleet/kit/environments.js`): App's `useEnvironment('locker', dir)` is `ctx.env` (the chosen environment's Locker section, `{ name, prod, vault, app, slot, resourceGroup, healthPath }`, or null). `load.js` `environmentPicks` finds what it names; `readAzure` prefers it to the saved picks, and `applyEnvironment` picks again whenever the environment (or the subscription) changes. `actions.js` `productionOk(ctx, what)` asks the kit's `productionQuestion` after Locker's own question before every change (set, copy, add to `.env`, disable, restart); a new change must call it too. `/env` is `environment`. `submit` hands each prompt line to the kit's `recordCommand` (Fleet's runbooks).
- **Config** (`src/config.js`): `~/.locker/config.json`, overridable with `LOCKER_HOME` (tests use it); `expiryDays` and `clearAfter` read their settings with the defaults. Change it only through `ctx.setConfig`: `App` saves its whole copy (and tells `onConfig`, which the guard reads).
- **Updates** (`@fleet/kit/update.js`): once a day, the newest `locker-v…` release; only in compiled builds, and off inside Fleet (`appTerminal()`'s `hosted`).
- **Hosted mode**: `cli.jsx` takes its streams from `appTerminal()` and gives them to its TTY check, `terminalMouse` and Ink's `render`, and draws on the alternate screen; it writes nothing else to the real terminal but the expiry notification's bell. `apps/fleet/CLAUDE.md` has the protocol; Fleet hosts Locker as its eighth space (`alt+8`, `ctrl+b l`).
- **Mouse** (`@fleet/kit/mouse.js`): as the siblings'; views register with `useMouse(ctx, handler)`, a view's rows start one line under its panel's top border (two in Drift, under its header row).
- **Theme and text**: a dark and a light palette in `src/theme.js`; every colour is read from `theme` while drawing; `@fleet/kit/text.js` (`fit`, `wrap`, `stringWidth`) for width-aware truncation, never `.length`.
- **Hush** (`src/pet.js`, `src/ui/Pet.jsx`): the octopus's pixel art and mood (`moodFor`, from `troubles`: expiring, broken, drift). `assets/` is generated from it by `scripts/logo.js`; don't hand-edit those files.

## Tests

`test/app.test.js` and `test/family.test.js` are end-to-end: they render `<App>` over `demoAzure()` and `demoLocal()` with `ink-testing-library`, type keys into stdin and assert on `lastFrame()`, on the demos' state and on the family's folder (no value in it). `test/azure.test.js` covers the ARM and Key Vault client against a fake fetch, the az sign-in and the clipboard guard; `test/drift.test.js` the keys, references, the matrix, the columns and expiry; `test/local.test.js` the folder's parsers and a real temp folder. `test/leaks.test.js` the leak scan, pure and in a real temp checkout (git with `GIT_CONFIG_GLOBAL` an empty file and the identity per commit, as CI has none). `test/rotate.test.js` the rotation, pure and end to end (`state.health` makes an app keep failing its check). `test/hygiene.test.js` the hygiene check: the judges with a fixed clock, a run over the demo, the headless JSON, the list end to end, and no value in any of it. `test/env.test.js` the environments (a temp folder with a `.fleet/project.json`), the production question and runbook recording. Use `until(check, what)` from `test/helpers.js` to wait for frames rather than fixed sleeps.

## Keeping things in sync

Adding or changing a key or command touches several places: the handler (view or `App.jsx`), `src/commands.js` for slash commands, the `?` window's sections in `src/help.js`, the status line's `HINTS` in `App.jsx`, and the tables in `README.md`. Commit messages are short sentences describing the change, without type prefixes.
