# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Runs a project's processes for you in the terminal, each with its own log, port and health. Bosun is a keyboard-driven terminal app built with Ink (React for the terminal) on Node 22+. It was started from slipway, and it's a sibling of Splice (a git client) and Trawl (a SQL client). Plain JavaScript ES modules with `.jsx` for components; no TypeScript, no linter config. The README is the user-facing spec; when behaviour changes, update it too.

It lives in the fleet repository, in `apps/bosun`, and is built on the fleet's shared kit, `@fleet/kit` (`packages/kit`; the root CLAUDE.md has its rules): `text.js`, `ui/parts.jsx`, `ui/hooks.js`, `ui/HelpView.jsx`, `ui/Palette.jsx`, `mouse.js`, `selection.js`, `clipboard.js`, `jsx-hooks.js`, `register.js`, `help-layout.js`, `keymap.js`, `usercommands.js`, `palette.js`, `run.js`, `credentials.js`, `claude-cli.js`, `family.js`, `update.js`, `theme.js` and the build, the kit's `scripts/build.js`. Import them as `@fleet/kit/<file>`; Bosun keeps no copy of any of them, and a change to one is a change to every app, so run every app's tests (`npm test` at the root). Anything only Bosun needs lives in its own file (Bosun's `structured.js`). `src/app.js` tells the kit which app this is (`configureApp`: the name `bosun`, the title `Bosun`, the version a build bakes in); import `VERSION` and `COMPILED` from it. `src/theme.js` fills the kit's `theme` object with Bosun's palette.

## Commands

```bash
npm install                                                    # once, at the repository root: every app and the kit
npm test                                                       # whole suite (node:test), here; npm run test:bosun at the root
node --import @fleet/kit/register.js --import ./src/app.js --test test/units.test.js      # one file
node --import @fleet/kit/register.js --import ./src/app.js --test --test-name-pattern="settings" test/*.test.js   # tests matching a name
npm start                                                      # run from the checkout (needs a real TTY)
npm run build                                                  # Bun-compiled executable for this machine → dist/ (the kit's scripts/build.js)
node scripts/logo.js                                           # regenerate assets/ from src/pet.js
```

`--import @fleet/kit/register.js` is required whenever Node loads `.jsx`: it installs a module hook (the kit's `jsx-hooks.js`) that compiles `.jsx` with esbuild on import. There is no dev build step. The tests also preload `--import ./src/app.js`, so the kit knows the app before any test file loads. CI runs Bosun's tests on Linux and Windows whenever `apps/bosun` or the kit changes, so path handling and line endings must work on both (`.gitattributes` forces LF).

The Ink patch is the repository's (`patches/ink+6.8.0.patch` at the root, applied by `npm install` there); the root CLAUDE.md says what it does, and the kit's `test/ink-patch.test.js` checks it.

Releases are automatic: every push to main that changes `apps/bosun` (or the kit, `patches/` or the root package files; not Markdown-only ones) releases Bosun from the root Release workflow as `bosun-v<version>`: the newest `bosun-v…` release with the patch raised, or `package.json`'s version when that's higher (bump it there for minor or major). It sets the version in the runner before building and commits nothing back, so `package.json` on main lags behind the releases. Compiled builds get the version via `process.env.BOSUN_VERSION` (defined by the kit's `scripts/build.js`, and written out in `src/app.js`), which also sets `COMPILED`; from a checkout `src/app.js` reads `package.json`, and the update check is skipped.

## Architecture

- **`src/crew.js`**: what to run, pure apart from reading files. `loadCrew(dir)` reads `bosun.json` (`readSpec` checks it, saying what's wrong in `problems`), else a `Procfile` (`parseProcfile`, `procfileProcs`: PORT from 5000, 100 apart, and the project's `.env`), else a compose file (`composeProcs`, read by `src/yaml.js`, a pure parser of just the YAML it needs: a process per service, `docker compose up --no-deps`), else package.json's `dev` (or `start`) script, split into processes when it's a `concurrently` line (`splitConcurrently`), with `dev:*` scripts that split the same way as profiles. `withProfile` applies one. `readEnvFiles` reads the `envFile`s into each process's `fileEnv` (parsed by `src/dotenv.js`, pure), which the supervisor puts between the terminal's settings and `env`; App's `/reload` restarts a process whose `fileEnv` changed. Also the log-line rules: `stripAnsi`, `isTrouble`, `portInUse`. `App` takes `loadCrew` as the `load` prop.
- **`src/supervisor.js`**: running the crew. `Supervisor` starts each process through the shell in its own process group (detached off Windows), keeps its last 3000 lines, and stops the whole tree (the group off Windows, `taskkill /T` on it), forcing it after a grace period. Objects change in place and `onChange` says so (with the process when only its log changed); `App` redraws at most every 80 ms, and for new lines only when their log is on screen (CrewView sets `ctx.logShown`). `startAll` honours `after`. A process that ends by itself is restarted as its `restart` says (`afterExit`, pure: the backoff and giving up, `RESTART_TIMES`, which App's `restartTimes` prop shortens in tests); a stop, `stop`, `setCrew` dropping it and `killAllNow` clear its timer, and nothing restarts once the supervisor is closed. `onEvent` tells App when one ended by itself. A process with `watch` has `fs.watch` watchers (recursive where the pattern needs it, which on Linux is `src/treewatch.js`'s `watchTree`, a watcher a folder leaving out the ones `skipsFolder` says nothing in can count, since Node's own watches every file; `src/watch.js`, pure, says which folders and which changes count) from its first start until it's stopped, removed or the supervisor is closed; a change restarts it after `debounce` ms. `checkPorts` (every 2 s from `App`) connects to each port and fetches the `health` page. Every supervisor registers itself, so `cli.jsx`'s `exit` handler (`killEverything`) stops everything however Bosun ends; keep it that way for anything new that starts a process that keeps running. `pidsOnPort` (lsof, netstat) and `killPids` are `/free`'s, given to `App` as props so tests stub them. `/ports` lists every listening TCP port through `src/ports.js` (`listeningPorts`: ss on Linux, else lsof, netstat and tasklist on Windows; the parsers and `markCrew` are pure), App's `listPorts` prop.
- **Recording and replay** (`src/recorder.js`, `src/replay.js`, `src/ui/ReplayView.jsx`): the supervisor's `recorder` (a `Recorder`, made by App for each new supervisor unless the `record` setting is off) hears every line from `push` and every change of `stateOf(p)` (`recordStates`, run with each `onChange`), and appends them as JSON lines to `~/.bosun/sessions/<projectHash>/<start>.jsonl`, the file made with the first line (pruned to `KEEP_SESSIONS`), cut at `MAX_BYTES`, and closed by `killAllNow`. `replay.js` is pure: `parseSession`, `Replayer.at(t)` (the crew at a moment, shaped as the supervisor's processes so CrewView's `statusSegment`/`portSegments`/`afterStatus` draw it), `marksOf`, `nextMark`, `timeline`. `/replay` (`actions.js`) lists them; the view is the `replay` overlay. The header also has the `profile` and the checkout (`git`: `src/githead.js` reads HEAD and the refs from the files, no git process), and a process's start records `{ type: 'start', env }` (`envHash` of its `fileEnv`, never the values) and a `git` event when the checkout moved; `setProfile` records `profile`. `r` in the view is `actions.js` `restore`: `src/restore.js` (pure) `restorePlan` says what to start, stop and switch and what it can't (a process gone, env files changed, another checkout), and the checkout goes to Splice as a copied `/checkout` line (`copiedNote`), never switched here.
- **CPU and memory** (`src/usage.js`): the parsers (`/proc/<pid>/stat` and `status`, macOS `ps`, Windows' one PowerShell `Win32_PerfFormattedData_PerfProc_Process` call), `treeOf`/`sumTrees` (a process with everything under it), `sparkline` and `memoryGrowing` are pure; `createSampler` takes the reads and the runner, one look at the machine per sample for every process. App samples every `sampleEvery` ms while the Crew view (or `/top`) shows, through the `sampleUsage` prop (tests stub it; `test/helpers.js` does by default), keeping `usage` and a minute of `samples` on each process, and says once a start when memory keeps growing past the `memoryAlert` setting.
- **Structured logs** (`src/structured.js`, pure): `parseStructured` reads a JSON line (pino, bunyan, Serilog compact, winston, plain level/msg/time) as `{ obj, time, level, message, fields }`, `structuredOf(line)` keeps it per line object (a WeakMap), `formatStructured` draws it, `troubleText` is the supervisor's trouble rule for it, and `parseFilter`/`passes` are CrewView's `ctrl+l` filter. `showLog` gives `TextViewer` a `rich` prop (each line's colour, trouble and `open`, ↵'s pretty object).
- **Tunnels** (`src/tunnel.js`, pure: `tunnelTool`, `tunnelArgs`, `tunnelUrl`, `tunnelProblem`, `installHint`): the supervisor's `openTunnel` starts cloudflared or ngrok through `tunnelSpawn` (App's prop; tests pass a fake child) as `p.tunnel`, and `closeTunnel` stops it, from `stop` (unless `restart` keeps it), a crash that isn't restarted, giving up and `killAllNow`. `onEvent` says `tunnel` (App copies the address) and `tunnel-closed`. App's `findTool` prop finds the tool.
- **Local HTTPS** (`src/https.js`): `httpsPort`/`httpsProblem` read `"https"`; `ensureCert` reads `~/.bosun/certs` or makes the certificate with mkcert (`find`, `exec`, `ask` injectable; App's `ensureCert` prop, asking before `mkcert -install`); `startHttpsProxy` ends TLS and passes requests and upgrades on. The supervisor's `serveHttps` runs it while the process runs (`tls`, `httpsProxy` options) and `stopHttps` stops it with the process and in `killAllNow`. `test/fixtures` holds a certificate for localhost valid to 2126.
- **IIS sites** (`src/iis.js`): a process with `iis` (`iisSpec`) has no command; the supervisor's `iisChild` makes an `IisChild` in place of a spawned child (the same `stdout`/`stderr`/'spawn'/'close' shape, plus 'pid' for its pool's worker, which becomes `p.pid` so CPU and memory are the worker's, and 'site' for its binding, which becomes `p.port` when bosun.json gives none and `p.site`, the health check's host and `o`'s address). It drives IIS through `iisControl` (appcmd, `exec`/`execSync`/`powershell` injectable; the supervisor's `iis` option, which tests fill with a fake): `stop`, `stopNow` (exit: only what Bosun started; a site already running is "adopted" and left), and `restart` calls `recycle` (its `build` with app_offline.htm, then `appcmd recycle apppool`) rather than stop and start. It polls the pool and its workers (`iisTimes.every`), the event log (`eventsEvery`, `eventIsSite`) and follows the ASP.NET Core stdout log and the W3C log (`tail.js`). The parsers (`parseAppcmd`, `parseBindings`, `parseSiteConfig`, `webConfigFacts`, `w3cJson`, `parseEvents`, `frameworkOfRelease`) are pure. Nothing may stop process 4 (`SYSTEM_PIDS`: http.sys's ports are System's): `killPids` skips it and `/free` says whose port it is.
- **Log files** (`src/tail.js`): `tailLogs(patterns, { cwd, env, onLine, every })` polls (fs.watch misses other processes' appends on Windows), following each pattern's newest file, from its end at first and a later file whole, and turns a W3C log's lines into structured JSON. The supervisor's `tailFor` follows a process's `logs` (its `tail` option) while it runs. `build` runs as `build && run`.
- **.NET Framework** (`src/appsettings.js`, `src/errorpage.js`, `src/dbwin.js`): the supervisor's `writeSettings` (its `appSettings` option, `writeAppSettings`) writes a process's `fileEnv` and `env` into the file its web.config's `<appSettings file>` names, before a start (a command's, from its `cwd`) and in `IisChild` before the pool starts or recycles (`settings`; an adopted site is recycled when they changed), never over a file without Bosun's `MARK`. `checkPorts` reads a 5xx health page (`httpStatus` keeps its body) through `errorPage` (pure: the yellow screen, ASP.NET Core's page, IIS's detailed errors, problem details) into the log once a start and status (`errorPageFor`). `"trace"`: `traceFor` subscribes to the supervisor's `debugOutput` (dbwin.js's shared `DebugOutput`, Windows only; tests pass a fake) with the process's tree (`fromTree`: its pid, or an `IisChild`'s `seen` workers); the helper is Windows PowerShell compiling `READER` (C#: the local and Global\ DBWIN buffers, each line `pid<TAB>parents<TAB>text`, exiting with Bosun's pid), started by the first subscriber and killed with the last; `parseDbwin` and the routing are pure.
- **.NET projects** (`src/dotnet.js`): `dotnetCrew` (loadCrew's last source, beside a dev script's) reads the web projects in the folder and the ones under it: an IIS site serving one (`readIisSites`, appcmd) is an `iis` process (built in place, or published to its folder inside the project: `msbuildPublishLine`, which applies the web.config transform), a .NET Framework one IIS Express built with MSBuild (`findMsbuild`, vswhere), an ASP.NET Core one `dotnet run --launch-profile`. `loadCrew`'s `dotnet` option passes `iisSites`, `msbuild` and `win` (tests). Pre-flight's `gatherIis`/`checkIis` and `toolsOf`/`checkTools` check what they need.
- **Groups** (`src/groups.js`, pure): `crewRows` (CrewView's rows, a heading per group, which `useListNav`'s `selectable` skips), `nextGroup` (`ctrl+g`), `namedProcs` (a group's name in `/start`, `/stop`, `/restart`; the supervisor's `startAll({ only })`), `afterTree`/`treeLine` (`/graph`).
- **Pre-flight** (`src/preflight.js`): `runChecks(facts)` and each `check*` are pure over facts that `gatherFacts(dir, crew, { part })` collects (`'ports'` before the first `startAll`, `'rest'` alongside it; everything injectable). App takes it as the `gatherFacts` prop and notes the checklist; `/preflight` shows it in the viewer. Problems never stop a start.
- **Hail checks** (`src/hailcheck.js`, `src/which.js`): a process's `test` (`testSpec`) runs when the supervisor's `onEvent` says `ready` (its port answered, and its health page, once per start): App's `runTests` calls the `runHail` prop (`hailTest`: `findOnPath('hail')`, PATHEXT on Windows, then `hail test` through run.js), keeps `p.tests` (`testOutcome`, pure) and pushes the report into the process's log.
- **The family** (`@fleet/kit/family.js`, shared and never edited here; `src/share.js`, `src/moods.js`, pure): hand-offs are command lines copied with `ctx.copy` (`/family`: `familyOffers`, `trawlLine` in `actions.js`; `t`: `troubleContext`, redacted). `/take` (and a bare context at the prompt, in `runLine`) handles `logline` and `exception` by searching the crew's logs. App's `pastedLine` opens the prompt with a pasted command or context. App's `activity` (`ctx.activity`) adds to the family's `logActivity` with the project: a crash or giving up (crewEvent, as `exitNews` says it), restarts and stops in `actions.js`, tunnels, `/move`; `/timeline` (a picker over `readActivity`, `p` through `actions`) and `/wiring` (`projectWiring`, by source) read it. App writes `familyMood(...)` with `writeMood` when it changes and reads the siblings' every `moodEvery` ms (`reactionTo`, one line until esc); the `familyMoods` setting turns both off, and tests point `FAMILY_HOME` at their temp home.
- **`src/projects.js`**: which project Bosun runs, pure apart from looking at folders. `startFolder` (cli.jsx): the folder given, else the current one when it has a crew, else the last project in the config's `projects` (newest first, `remember` keeps eight; App adds one each time a crew with processes is read). `/move` (`actions.js` `move`) resolves a path or a folder beside the project (`resolveFolder`), offers `choices` without one, asks before stopping running processes, then App's `moveTo` stops and disposes the supervisor and reads the new folder as on opening. The project is `dirRef` in App (`ctx.dir` is a getter for it), shown in the header and the window title.
- **`@fleet/kit/run.js`**: where one-off programs are started (`!`); the crew's long-running ones are the supervisor's. Nothing it starts has a terminal, so nothing may wait on a prompt; an abort kills the whole tree (`taskkill /T` on Windows). Its `callSignal(signal)` gives one call (a fetch) a signal of its own under a long-lived one, tied to it only until `done()`, so many calls leave no listeners piled on it.
- **`src/actions.js`**: every user-facing operation, written once. Keys and slash commands call these with `ctx`. Questions before anything destructive live here (`ctx.confirm({ ..., danger: true })`).
- **`src/commands.js`**: the slash-command table (`name`, `args`, `desc`, optional `complete`, `run(ctx, rest)`) and completion. Args in `[brackets]` are optional, so picking the command runs it at once.
- **`src/ui/App.jsx`**: layout, focus, the prompt, overlays, the activity log and **`ctx`**: a stable object exposing `data` and `config` (getters), `task` (a visible, cancellable job with the spinner), `note`, `confirm`, `askSecret` / `askText` (a masked or plain field in the confirm's place), `prefill`, `showText` (text, or coloured `lines`), `showPicker`, `copy`, `setConfig`. A view that takes keys the app would otherwise use (a search being typed) sets `ctx.claimsKey(input, key)`, calls `ctx.claimed()` as it handles a key it claims (Ink calls the handlers in no fixed order, so the dispatcher may see the claim already dropped, as when esc clears a search), and clears it when it unmounts. Read the `Object.assign(ctx, {...})` block before adding an action.
- **Claude** (`w`, `/why`): `actions.js` `why` sends a process's last 400 lines through `claude-cli.js` `ask` with read-only `Read`, `Grep`, `Glob`, in the project's folder. `App` takes `ask` as the `askClaude` prop; tests stub it, as they do `openUrl` (the browser, from `cli.jsx`).
- **`src/ui/*View.jsx`**: one component per tab: Crew (`CrewView.jsx`: the list, and beside it the log of the one under the cursor or, with `a`, all of them merged by time; `ctrl+f` searches that log through `@fleet/kit/search.js`, claiming `ctrl+f`, and `n N esc` while a search is up, with `ctx.claimsKey` (`/` is the prompt's everywhere, as in the siblings), and `e` keeps the lines `isTrouble` picks) and Log. `TextViewer` searches the same way, and takes `e` for a `log`. Views must check `ctx.viewHasKeys()` (or `ctx.overlayHasKeys()` in overlays) at the start of their `useInput` handlers. `useListNav` in `@fleet/kit/ui/hooks.js` is the shared cursor and scroll logic.
- **Mouse** (`@fleet/kit/mouse.js`, `@fleet/kit/selection.js`; `apps/splice/docs/mouse.md` has the design): `terminalMouse` strips mouse reports out of stdin before Ink sees them and hands them to `App` as the `mouse` prop; tests pass a fake (`test/clicks.test.js`). Components register with `useMouse(ctx, handler)`; a view's rows start one line under its panel's top border. Views name their `useInput` handler `keys` so a double-click can call `keys('', { return: true })`.
- **Notifications** (`src/notify.js`, Trawl's and Splice's plus `exitNews`): `App` calls the `notify` prop (cli.jsx writes a bell and OSC 9 / OSC 777) when a `task` that wasn't cancelled took over `notifyAfter` seconds (10), and from the supervisor's exit event when a process crashed (the first time in a run of restarts) or gave up. The `notify` setting turns it off; tests pass a recorder or nothing.
- **Updates** (`@fleet/kit/update.js`): once a day, the newest `bosun-v…` release of the fleet repository, from GitHub's releases API, then `gh api` while the repository is private. A newer release is installed in the background next to the executable, checked against `SHA256SUMS.txt`. Release file names must match `buildTargets` in the kit's `update.js` (the kit's `scripts/build.js` builds those). `cli.jsx` passes `checkUpdate` and `installUpdate` only in compiled builds.
- **Config** (`src/config.js`): `~/.bosun/config.json`, overridable with `BOSUN_HOME` (tests use it). Change it only through `ctx.setConfig`: `App` saves its whole copy. A new setting is a row in `src/settings.js` plus the README's Settings section.
- **Theme and text**: a dark and a light palette in `src/theme.js` (`DARK`, `LIGHT`), as Splice's: `applyTheme(config)` copies one into `theme` (the Theme setting, `auto` reading `COLORFGBG`) and the accent over it, at start-up in `cli.jsx` and from `/settings`. Every colour is read from `theme` while drawing: a module-level table of colours is a function (`STATUS_COLOUR()`) or getters, never values copied at import; use `BULLET` instead of `⏺`, and `@fleet/kit/text.js` (`fit`, `wrap`, `stringWidth`) for width-aware truncation, never `.length`.
- **Squawk** (`src/pet.js`, `src/ui/Pet.jsx`): the mascot's pixel art and mood. `assets/` is generated from it by `scripts/logo.js`; don't hand-edit those files.

## Tests

`test/app.test.js` and `test/clicks.test.js` are end-to-end: they render `<App>` with `ink-testing-library`, type keys into stdin and assert on `lastFrame()`. `test/helpers.js` `start` gives App a quiet crew that never starts unless a test passes `dir` (a folder from `project(spec, files)`, whose processes are small node scripts) or `load`. `test/crew.test.js` covers crew.js and the supervisor with real processes, including that a stopped process lets go of its port. Use `until(check, what)` from `test/helpers.js` to wait for frames rather than fixed sleeps. `test/units.test.js` covers the pure modules.

## Keeping things in sync

Adding or changing a key or command touches several places: the handler (view or `App.jsx`), `src/commands.js` for slash commands, the `?` window's sections in `src/help.js`, and the tables in `README.md`. Commit messages are short sentences describing the change, without type prefixes.
