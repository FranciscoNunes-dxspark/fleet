# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Infrastructure as code in the terminal: what a Terraform (or OpenTofu) plan or an Azure what-if of a Bicep or ARM file would change, resource by resource and attribute by attribute, what drifted, what the state holds; what it would deploy insecurely; and `chart check` and `chart security` for a pipeline. It plans, and applies on request only what it planned and showed (`/apply`: a plan file it saved itself, or the what-if on screen; `/deploy`: a what-if then its deployment), behind a typed confirmation. Chart is a keyboard-driven terminal app built with Ink (React for the terminal) on Node 22+, a sibling of Splice, Trawl, Sonar, Bosun, Hail, Keel, Wharf, Locker, Mooring and Bilge. Plain JavaScript ES modules with `.jsx` for components; no TypeScript, no linter config. The README is the user-facing spec; when behaviour changes, update it too.

It lives in the fleet repository, in `apps/chart`, and is built on the fleet's shared kit, `@fleet/kit` (`packages/kit`; the root CLAUDE.md has its rules). Import the kit's files as `@fleet/kit/<file>`; Chart keeps no copy of any of them, and a change to one is a change to every app, so run every app's tests (`npm test` at the root). `src/app.js` tells the kit which app this is (`configureApp`: the name `chart`, the title `Chart`, the version a build bakes in); import `VERSION` and `COMPILED` from it. `src/theme.js` fills the kit's `theme` object with Chart's palette (indigo).

## Commands

```bash
npm install                                                    # once, at the repository root: every app and the kit
npm test                                                       # whole suite (node:test), here; npm run test:chart at the root
node --import @fleet/kit/register.js --import ./src/app.js --test test/plan.test.js        # one file
node --import @fleet/kit/register.js --import ./src/app.js --test --test-name-pattern="what-if" test/*.test.js   # tests matching a name
npm start                                                      # run from the checkout on this folder (needs a real TTY)
npm run demo                                                   # run against the in-memory demo infrastructure (needs a real TTY)
node bin/chart.js check --demo                                 # the headless check, on the demo
npm run build                                                  # Bun-compiled executable for this machine → dist/ (the kit's scripts/build.js)
node scripts/logo.js                                           # regenerate assets/ from src/pet.js
```

`--import @fleet/kit/register.js` is required whenever Node loads `.jsx`. The tests also preload `--import ./src/app.js`. CI runs Chart's tests on Linux and Windows whenever `apps/chart` or the kit changes, so paths must work on both (a found file's path is always `/`-separated). Nothing in the suite runs terraform, tofu or az.

Releases are automatic, as every app's: a push to main that changes `apps/chart` (or the kit, `patches/` or the root package files) releases it as `chart-v<version>` (root CLAUDE.md, "Releases"). Compiled builds get the version via `process.env.CHART_VERSION`.

## Architecture

- **The provider** (`src/iac.js`): everything Chart reads and runs goes through one object, `createChart({ run, stream, fetch })`: `detect(dir)` (`tfDirs`, `bicep`, `params`, `saved`), `plan(dir, { bin, refreshOnly, workspace, varFile, keep })` (a plan into a file, `show -json` of it; removed, or with `keep` left in the provider's own `mkdtemp` folder as the plan's `planFile`), `discard(planFile)`, `cleanup()` (App's unmount and cli.jsx's exit), `workspace`, `apply(dir, { planFile, onLine })`, `state`, `init`, `whatIf(dir, { file, resourceGroup | location, params })`, `readFile`, `graph` (`terraform graph`), `locate(dir, change)` (`resource "type" "name"` in the `.tf` files: `{ path, line }`), `sources(dir)` (`readSources`: the `.tf`, `.tfvars`, `.bicep` and `.bicepparam` files' text, for the static checks; reads only). Command lines run through the kit's `run.js` with `-input=false`; `explain()` turns a missing program, a missing `az login` or a missing `init` into a sentence. **Everything put in a command line is checked by `safeArg()`**, and `bin` is one of `BINARIES`: keep that for any new command. **Only two things change infrastructure, and only behind the guardrails**: `apply` takes nothing but a `planFile` this provider saved (a `Set`; never twice, the file removed afterwards whatever happened; a stale plan's error is `explain`ed), and streams through the kit's `run.js` with `onLine` (the provider's `stream`); `deploy` (`az deployment group|sub create`) returns only the output names. Both are called only from `actions.apply` / `deploy` (`deployWhatIf`), after `applyLines` (what it does, the destroys first) and `confirmByName` (the environment's, or else the workspace's or resource group's, name typed exactly into a plain `SecretPrompt`, then `productionQuestion` in production). `/apply` refuses a plan with no `planFile` (an `/open`ed one, or one spent by a failed apply) and one made for another environment (`source.env`). `ctx.task`'s `start(signal, { line })` gets the output into the task's entry as it comes. Don't add any other way to apply. `src/demo.js` `demoChart()` has the same interface (`calls` is the tests' handle: `state` is one of the provider's methods).
- **Plans** (`src/plan.js`, `src/diff.js`, pure): `parseTerraformPlan`, `parseTerraformState`, `parseWhatIf`, `parseAny` give one shape: a plan is `{ tool, version, changes, drift, outputs, dependsOn, security, errored, planFile? }` and a change `{ address, type, name, module?, mode, provider, action, reason?, diff, id?, resourceGroup?, pricing }`, `action` one of `ACTIONS` (`replace` for a delete and a create). `attributeDiff(before, after, { unknown, beforeSensitive, afterSensitive, forces })` flattens to leaves and compares; **a value Terraform marks sensitive is replaced by `SENSITIVE` here, so it never reaches the screen, the clipboard, a report or the activity log**: keep every new display going through it (`diffLines`, `valueLines`). What-if deltas are flattened, `NoEffect` marked `noise`. `summarize`, `summaryLine`, `ordered` (what loses something first).
- **Costs** (`src/costs.js`, pure but for the `prices` it's given): its header comment is the mapping table (which types are priced by what; everything else is "no price", never a guess). `pricingSpec(type, values, marks)` runs at parse time (plan.js) and leaves each change a `pricing: { before, after }` of a few non-secret facts (sku, size, count, OS, location, parents), nothing marked sensitive or unknown; `pricingPlan(spec)` says which price-list items to ask for (`query`) and how to pick one price from them (several different ones is no price); `planCosts(plan, { prices, currency })` gives `{ byAddress, total, priced, unpriced, usage, failed }`; `money`, `costWords`, `totalWords`, `costLines` say them. The provider's `prices(query, { currency })` asks the Retail Prices API (`fetch` is injectable: tests pass a fake), follows `NextPageLink`, and keeps each query's promise for the session (a failure isn't kept); `priceFilter` builds the `$filter`. `actions.price` runs after a plan, what-if or `/open` without holding up the next command, and keeps the costs with `for: plan` (`costsOf(data)` ignores another plan's); `config.costs === false` turns it off, `config.currency` (`/currency`) picks the currency. The demo has `DEMO_PRICES` and records `prices` calls.
- **Security** (`src/security.js`, pure; findings in the kit's `findings.js` shape, `{ rule, severity, title, where, line?, why, fix, excerpt }`, plus `resource`, `type`, `attribute`): the judges, keyed by resource type in `JUDGES` (an azurerm type and its Microsoft.* type share one judge, `dialect` 'tf' or 'arm' saying which shape it reads; a few AWS ones), each returning `{ rule, attribute, excerpt }` hits that `RULES` (severity, title, why, a fix naming the attribute to set) makes into findings. `parseTerraformPlan` and `parseWhatIf` run `planFindings` over what each change leaves deployed and keep `plan.security` (`where`: the address); Terraform's after state goes through `knownValues` first, so **what it marks sensitive or unknown is never read** and can't reach an excerpt. `sourceFindings(path, text)` reads a file statically: `readTerraform` / `readBicep` gather each resource's literal values into the same shapes (an expression is an `Unknown`) with each attribute's line, so the same judges say the same with `path:line`; then passwords written into `.tf`/`.tfvars`/`.bicep`/`.bicepparam`, Bicep's secret parameters without `@secure()`, and the kit's `codescan.js` `scanText` secret rules (a password's excerpt is `redact`ed). `folderFindings(files)` adds what shows only across resources (an S3 bucket no public access block points at; a storage account an `azurerm_storage_account_network_rules` closes); `mergeFindings` drops a plan's finding a file already has. `actions.securityOf(data, config)` gives the plan's and the files' findings without `config.securityIgnore`; `/security` (and the Security view, the first time it's shown) reads the files into `data.sources`. A new rule: its entry in `RULES`, its judge (both dialects where Azure has both), a test of each shape, good and bad, and the README's table.
- **`src/rows.js`** (pure): marks, words and colours of actions, `changeRows`, `stateRows`, `findChange`, `siteOf` (an App Service app as the family's `site`). **`src/share.js`**: `markdownReport`. **`src/headless.js`**: `chart check` (`runHeadless(args, { provider, config, write })` resolves the exit code; `fails(plan, failOn)`) and `chart security` (`runSecurity(args, { provider, config, write, writeFile })`: a folder's files read without running anything, `--plan` to plan it too, or a plan or what-if file; `--json` is the kit's `securityJson`, `--sarif` its `toSarif`, only findings with a line counted as files), which `cli.jsx` runs before asking for a terminal.
- **`src/actions.js`**: every user-facing operation, written once; keys and slash commands call these with `ctx`. `whatIfArgs` reads `/whatif`'s arguments, the last ones (the config's `whatIf`) filling the gaps.
- **`src/commands.js`**, **`src/help.js`**: the slash-command table and completion (only a command's first argument completes); the `?` window's sections.
- **`src/ui/App.jsx`**: as Bilge's (its CLAUDE.md), with `data` `{ found, plan, drift, source: { kind: terraform | bicep | file, label, dir?, env?, workspace? }, state, costs?, graph?, sources? }` (`costs` and `graph` carry `for`, the plan they are of; `sources` is `/security`'s read of the folder's files, `{ dir, files, findings }`): `drift` is the latest plan's or refresh-only plan's, kept apart from `plan` so `/drift` never empties Changes. It only looks at the folder on opening; nothing polls. `ctx.refresh` (ctrl+r) is `again`.
- **`src/ui/ChangesView.jsx`** (Changes, and Drift with `drifted`; its `! high` column from `security`, the plan's findings by address), **`SecurityView.jsx`** (`securityRows`: the plan's, then the files'), **`StateView.jsx`**, **`LogView.jsx`**, **`DependsView.jsx`**, **`Viewer.jsx`**: views check `ctx.viewHasKeys()` first; `useListNav` from the kit. In Changes, `g` (taken before the list's own "top") opens Depends on the selected change (`ctx.openDepends`).
- **What depends on what** (`src/graph.js`, pure and importing nothing, as plan.js uses it): one shape, `dependsOn` `{ address → [addresses] }` over the plan's change addresses. `parseTerraformPlan` fills it from `configuration` (`planDependencies`: each resource's `expressions` references, `count`/`for_each`, `depends_on`, what a module call is given; instances by `configAddress`), null without one; `parseWhatIf` from the ids (`idDependencies`); `/graph` from `terraform graph` (`parseDot`, old `[root] … (expand)` and new forms) into `data.graph`. `actions.dependenciesOf(data)` picks. `dependencyRows` is the tree (a node under several drawn once in full, `repeat` elsewhere; cycles still shown), `dependentsOf`, `affectedBy`, `affectsLine` ("Replacing X affects Y, Z") for the detail and `applyLines`.
- **The family** (`@fleet/kit/family.js`, shared and never edited here; `src/moods.js`, pure): Chart is in `FAMILY` (role `IAC`, Plot). `t` hands Splice a `file` context (where a resource is declared), `s` hands Locker a `site`. It takes no context. Plans, what-ifs and drift go to the activity log with the folder; Plot's mood to `writeMood`; tests point `FAMILY_HOME` at a temp folder (`tempHome`).
- **Environments** (`@fleet/kit/environments.js`): App's `useEnvironment('chart', cwd)` keeps the frames red for a production one and the header's name current; actions read `ctx.env()` (`environmentFor`, read when asked, so a `/env` just typed counts at once). The `chart` section's `workspace` goes to terraform as `TF_WORKSPACE` and `varFile` as `-var-file` (`tfOpts`); `resourceGroup` and `parametersFile` fill `/whatif`'s gaps ahead of the last ones (`whatIfArgs`'s `env`), and are never saved as the last ones. `/env` is `describeEnvironments` / `setEnvironment(dir, name, { by: 'chart' })`. A plan's `source.env` is the environment it was made for. `runLine` calls `recordCommand('chart', line)` once for each slash command (or pasted context, as `/take …`) it ran.
- **Config** (`src/config.js`): `~/.chart/config.json`, overridable with `CHART_HOME`. Change it only through `ctx.setConfig`.
- **Updates, hosted mode, mouse, theme and text**: as Wharf's (its CLAUDE.md).
- **Plot** (`src/pet.js`, `src/ui/Pet.jsx`): the puffin's pixel art and mood. `assets/` is generated from it by `scripts/logo.js`; don't hand-edit those files.

## Tests

`test/app.test.js` and `test/family.test.js` are end-to-end: `<App>` over `demoChart()` with `ink-testing-library`, typing keys and asserting on `lastFrame()` and `provider.calls`. `test/plan.test.js` covers the parsers, the attribute diff (sensitive values never in it), the state and what-if shapes and the rows; `test/iac.test.js` the command lines against a fake `run`, a folder on disk, `locateResource`, `chart check` and the report; `test/costs.test.js` the pricing (specs, picks, totals, the provider against a fake `fetch`, the views); `test/env.test.js` environments and recording; `test/graph.test.js` the dependencies (configuration, DOT, ids), the tree and the Depends view; `test/apply.test.js` the plan files kept and applied (a fake `run` and `stream`) and `/apply` end to end; `test/security.test.js` each judge on Terraform's and ARM's shapes (good and bad), sensitive values unread, the source readers with `path:line`, `chart security` (text, `--json`, `--sarif`, `--plan`, ignores) and the Security view over the demo (whose plan, what-if and `DEMO_SOURCES` are insecure on purpose). A test file that writes a password builds it from pieces and starts with `// bilge-ignore-file`. Use `until(check, what)` to wait for frames rather than fixed sleeps.

## Keeping things in sync

Adding or changing a key or command touches several places: the handler (view or `App.jsx`), `src/commands.js` for slash commands, the `?` window's sections in `src/help.js`, the footer `HINTS` in `App.jsx`, and the tables in `README.md`. Commit messages are short sentences describing the change, without type prefixes.
