# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Containers and pods in the terminal: what's running (a compose project's together), CPU and memory, live logs, and starting, stopping, restarting and removing them. Wharf is a keyboard-driven terminal app built with Ink (React for the terminal) on Node 22+, a sibling of Splice, Trawl, Sonar, Bosun, Hail and Keel. Plain JavaScript ES modules with `.jsx` for components; no TypeScript, no linter config. The README is the user-facing spec; when behaviour changes, update it too.

It lives in the fleet repository, in `apps/wharf`, and is built on the fleet's shared kit, `@fleet/kit` (`packages/kit`; the root CLAUDE.md has its rules). Import the kit's files as `@fleet/kit/<file>`; Wharf keeps no copy of any of them, and a change to one is a change to every app, so run every app's tests (`npm test` at the root). Anything only Wharf needs lives in its own file (`rows.js`). `src/app.js` tells the kit which app this is (`configureApp`: the name `wharf`, the title `Wharf`, the version a build bakes in); import `VERSION` and `COMPILED` from it. `src/theme.js` fills the kit's `theme` object with Wharf's palette (teal).

## Commands

```bash
npm install                                                    # once, at the repository root: every app and the kit
npm test                                                       # whole suite (node:test), here; npm run test:wharf at the root
node --import @fleet/kit/register.js --import ./src/app.js --test test/docker.test.js      # one file
node --import @fleet/kit/register.js --import ./src/app.js --test --test-name-pattern="stops" test/*.test.js   # tests matching a name
npm start                                                      # run from the checkout against the real Docker (needs a real TTY)
npm run demo                                                   # run against the in-memory demo Docker (needs a real TTY)
npm run build                                                  # Bun-compiled executable for this machine → dist/ (the kit's scripts/build.js)
node scripts/logo.js                                           # regenerate assets/ from src/pet.js
```

`--import @fleet/kit/register.js` is required whenever Node loads `.jsx`: it installs a module hook (the kit's `jsx-hooks.js`) that compiles `.jsx` with esbuild on import. There is no dev build step. The tests also preload `--import ./src/app.js`, so the kit knows the app before any test file loads. CI runs Wharf's tests on Linux and Windows whenever `apps/wharf` or the kit changes, so path handling and line endings must work on both (`.gitattributes` forces LF). Nothing in the suite needs Docker.

Releases are automatic, as every app's: a push to main that changes `apps/wharf` (or the kit, `patches/` or the root package files; not Markdown-only ones) releases it as `wharf-v<version>` (root CLAUDE.md, "Releases"). Compiled builds get the version via `process.env.WHARF_VERSION`.

## Architecture

- **The provider** (`src/docker.js`): everything Docker goes through one object with one interface, `createDocker({ run })`: `containers`, `stats`, `images`, `logs`, `inspect`, `act(verb, ids)`, `remove`, `removeImage`, `pull`, `prune`. It runs the `docker` command line through the kit's `run.js` (nothing may wait on a prompt; an abort kills the tree), so Docker contexts and `DOCKER_HOST` apply as they do in the shell, and no socket or native module is needed (the Bun build must keep working). The parsers (`parseContainers`, `parseStats`, `parseImages`) read `--format "{{json .}}"` output and are pure. **Everything passed to the shell is checked by `safe()`** (what Docker would have named, never more): keep that for any new operation. `src/demo.js` `demoDocker()` has the same interface for `--demo` and the tests; a new operation needs both, and its test.
- **Kubernetes** (`src/kube.js`, `src/demokube.js`, `src/kubeactions.js`, `src/ui/PodsView.jsx`): the same shape for `kubectl`: `createKube({ run })` (`pods`, `top`, `logs`, `describe`, `deletePod`, `rolloutRestart`, `namespaces`, `contexts`, `useContext`, `current`), `parsePods` / `parseTop` / `kubeProblem` pure, and every name passed to the shell checked by `safeName()` (a DNS name) or the context rule. `demoKube()` is its demo and `state` its test handle. App reads the cluster only while the Pods view is on screen (`reloadKube`, `kubeData`: kubectl may not be installed, and Docker's views must work without it); tasks that change it pass `refreshKube: true`. The namespace is kept in the config (`kubeNamespace`). `/context` changes kubectl's own current context, so it asks.
- **`src/rows.js`**: pure. What the lists draw: `containerRows` (a heading per compose project, standalone last, running first), `findContainer` / `targetsOf` (a name, an id start, `project/service`, a project, `all`), `stateLabel` / `stateTone`, `shortBytes`, `shortCpu`, and the log's `logLine` / `logTone` / `isTrouble`.
- **`src/actions.js`**: every user-facing operation, written once. Keys and slash commands call these with `ctx`. Questions before anything destructive live here (`ctx.confirm({ ..., danger: true })`): stopping or killing several containers, removing, pruning, removing an image (and forcing one a container uses). `explain()` puts "Docker isn't running" in front of a daemon error.
- **`src/commands.js`**: the slash-command table (`name`, `args`, `desc`, optional `complete`, `run(ctx, rest)`) and completion. Args in `[brackets]` are optional, so picking the command runs it at once.
- **`src/ui/App.jsx`**: layout, focus, the prompt, overlays, the activity lines and **`ctx`** (read the `Object.assign(ctx, {...})` block before adding an action): `provider`, `data` and `config` (getters), `task` (a visible, cancellable job with the spinner; `refresh: true` reads Docker again after), `note`, `confirm`, `copy`, `showText`, `showLogs`, `refresh`. It reads Docker on opening and every `pollEvery` ms (the `pollEvery` prop; 0 in tests), one read at a time, the stats after the list so they never hold it up; a failure keeps what was on screen and says why in the header. Uppercase shortcuts are alt+letter (`shortcutKey` from the kit's `keymap.js`, through `useKeyTranslation`), so a view's handler sees `G`, and the help says `alt+g`.
- **`src/ui/*View.jsx`**: one component per tab: Containers, Images, Log. Views must check `ctx.viewHasKeys()` at the start of their `useInput` handlers so keys don't fire while the prompt, an overlay or a confirm has focus. `useListNav` in `@fleet/kit/ui/hooks.js` is the shared cursor and scroll logic. `Viewer.jsx` shows text over the view; with a `source` it asks again every moment (a container's log, which follows the end until you scroll up).
- **The family** (`@fleet/kit/family.js`, shared and never edited here; `src/share.js`, `src/moods.js`, pure): Wharf is in `FAMILY` and takes `logline` contexts. `t` in a log (`Viewer.jsx`, `actions.js` `shareTrouble`) copies the newest line that reads as trouble as `/take family:v1:logline:…` for Sonar, Hail or Bosun (`copiedNote` also tells Fleet, which switches there); `/take` (and a bare context at the prompt, in `runLine`) looks for a line in the running containers' and pods' last 1000 lines and opens the first log that has it with the line searched (`Viewer`'s `search` prop). Anything else is `notMine`. What changes something (`task`'s `activity` option, in `actions.js` and `kubeactions.js`) goes to the family's activity log with the compose project's folder when it has one; Bark's mood goes to `writeMood` when it changes and the siblings' are read every `moodEvery` ms (`reactionTo`, one line until esc); the `familyMoods` setting turns both off, and tests point `FAMILY_HOME` at a temp folder (`tempHome`). The other apps don't offer Wharf as a place to send a line yet: that is a change in each of them.
- **Config** (`src/config.js`): `~/.wharf/config.json`, overridable with `WHARF_HOME` (tests use it). Change it only through `ctx.setConfig`: `App` saves its whole copy.
- **Updates** (`@fleet/kit/update.js`): once a day, the newest `wharf-v…` release of the fleet repository; only in compiled builds, and off inside Fleet (`appTerminal()`'s `hosted`), which updates as one.
- **Hosted mode**: `cli.jsx` takes its streams from `appTerminal()` and gives them to its TTY check, `terminalMouse` and Ink's `render`, and draws on the alternate screen; it writes nothing else to the real terminal. `apps/fleet/CLAUDE.md` has the protocol.
- **Mouse** (`@fleet/kit/mouse.js`, `@fleet/kit/selection.js`; `apps/splice/docs/mouse.md` has the design): `terminalMouse` hands events to `App` as the `mouse` prop; tests pass nothing. Views register with `useMouse(ctx, handler)`; a view's rows start one line under its panel's top border.
- **Theme and text**: a dark and a light palette in `src/theme.js`; every colour is read from `theme` while drawing (a module-level table of colours is a function or getters, never values copied at import); use `BULLET` instead of `⏺`, and `@fleet/kit/text.js` (`fit`, `wrap`, `stringWidth`) for width-aware truncation, never `.length`.
- **Bark** (`src/pet.js`, `src/ui/Pet.jsx`): the seal's pixel art and mood. `assets/` is generated from it by `scripts/logo.js`; don't hand-edit those files.
- **Shells** (`src/shell.js`, pure; `src/ui/ShellPane.jsx`): `e` and `/shell` (`actions.js` `shell`, `kubeactions.js` `shell`, which asks which container of a pod with several, as `c` does for its log) call `ctx.openShell({ title, make(tty) })`, `make` being `dockerShell` or `kubeShell` (names checked by `safe()`/`safeName()`; `sh -c` running bash, else sh). Outside Fleet `cli.jsx` gives App `runInTerminal`: the mouse off, cooked mode, off the alternate screen, `spawnSync` with the terminal inherited (blocking, so Node reads none of the keys meant for the shell), then everything back and a `'resize'` for Ink to draw its whole frame again. Hosted (and `--demo`) there's no `runInTerminal`, so the exec runs with `-i` only in the `shell` overlay: `ShellPane` spawns it through App's `spawnShell` prop (`demo.js` `demoShell` in --demo and the tests) and keeps the pane's state with `paneOutput`/`paneKey`/`paneView`; App leaves the pane's capitals and ctrl+c alone. `/exec` runs one command and shows its output.

The viewer's search is `@fleet/kit/search.js`, shared with Bosun, Hail and Splice.

## Tests

`test/app.test.js` is end-to-end: it renders `<App>` over `demoDocker()` with `ink-testing-library`, types keys into stdin and asserts on `lastFrame()` and on the demo's state (`provider.state.calls`). Nothing reaches Docker. `test/docker.test.js` covers the parsers, the shell-safety rule and the provider's commands against a fake `run`; `test/kube.test.js` the kubectl parsers, shell-safety rule and commands; `test/rows.test.js` the pure modules, the commands and Bark; `test/shell.test.js` the shell's commands, the pane's state, and the pane and the hand-over in the app. Use `until(check, what)` from `test/helpers.js` to wait for frames rather than fixed sleeps.

## Keeping things in sync

Adding or changing a key or command touches several places: the handler (view or `App.jsx`), `src/commands.js` for slash commands, the `?` window's sections in `src/help.js`, the footer `HINTS` in `App.jsx`, and the tables in `README.md`. Commit messages are short sentences describing the change, without type prefixes.
