# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Pilot maps an ASP.NET MVC / ASP.NET Core project for Claude Code: controllers, `.cshtml` views, layouts, partials, view components, templates, bundles, TypeScript, JavaScript, LESS, SCSS and CSS as one graph, with the requests pages make and what answers them, their UI components, a complexity score and stylesheet split suggestions; asked through a headless CLI (`pilot page /Orders/Edit`, `pilot selector .btn-save`, `pilot impact _Header`), the same queries as an MCP server (`pilot mcp`), or a web UI with graphs (`pilot ui`), with a skill `pilot init` writes into a project. Plain JavaScript ES modules on Node 22+, no Ink and no TUI: it has no screen of its own, so it isn't in the family's `FAMILY`/`ROLES` (`family.js`) and Fleet doesn't host it (as Helm isn't in `FAMILY`). It has no `pilot security` either: it only reads the project and holds nothing secret. The README is the user-facing spec; when behaviour changes, update it too.

It lives in the fleet repository, in `apps/pilot`, built on `@fleet/kit` (`app.js` for its names, `mcp.js` for the MCP server, `update.js`'s names for releases; the root CLAUDE.md has the kit's rules). `src/app.js` tells the kit which app this is (`configureApp`: `pilot`, `Pilot`, `process.env.PILOT_VERSION`); `bin/pilot.js` imports it first and is also the build's entry (`"fleet": { "entry": "bin/pilot.js" }`).

## Commands

```bash
npm test                                                  # whole suite (node:test); npm run test:pilot at the root
node --import ./src/app.js --test test/parsers.test.js    # one file
node bin/pilot.js --root test/fixtures/shop page /Orders  # try it on the fixture
npm run build                                             # Bun-compiled executable → dist/
node scripts/logo.js                                      # regenerate assets/ (the ship's wheel)
```

## Architecture

- **Reading** (`src/parse/`, pure, text in → plain data out, lines 1-based): `razor.js` (`parseRazor`: model, layout, title, partials and templates, child actions, components, sections with their extent, `RenderSection`/`RenderBody`, scripts, styles, bundles, classes/ids/data- attributes/handlers, links to actions, inline `<script>`/`<style>` through the other parsers with their lines moved; `callArgs` splits a call's arguments and is shared with C#), `script.js` (imports, definitions, selectors and classes, route-shaped strings; `selectorTokens`), `style.js` (a brace scanner: rules with composed selectors and `&`, classes/ids each rule adds, imports, variables, mixins, `@media` context; `less`, `scss`, `css`), `csharp.js` (controllers, actions, views returned, verbs, routes, view components, `BundleConfig`, `MapRoute`), `config.js` (bundleconfig, compilerconfig, tsconfig, webpack). `src/text.js` has the shared helpers (`lineIndex`, `stripComments`, `stripRazorComments`, `matchBrace`). Patterns, not compilers: anything decided at run time goes to `dynamic`.
- **Finding files** (`src/walk.js`): `walk(root)` → `[{ rel, kind, size, mtime }]`, `SKIP_DIRS`, `isVendor` (libraries are listed, not read for selectors unless `--vendor`).
- **The index** (`src/index.js`, `ProjectIndex`): `build()` walks, reuses cached parses by size and time (`cacheFile`, `PILOT_CACHE`; bump `CACHE_VERSION` whenever a parser's output changes), then `link()` builds `edges`/`reverse` between files and nodes (`action:[Project:][Area/]Controller/Action`, `bundle:~/path`). Edge kinds: `layout`, `partial`, `template`, `component`, `component-class`, `child-action`, `renders`/`renders-partial` (action → view), `script`, `style`, `import`, `source` (built file → its source), `link`, `calls`. `dependents(id)` walks back along the kinds that carry a change (not `link`/`calls`). `resolveView` is MVC's lookup, then a guess by name; `appPaths` resolves `~/` and `wwwroot`; `sourcesOf` follows built files to sources; `routeToAction` matches attribute routes (`routeSegment`, constraints) then conventional ones per project; `buildSymbols` makes `symbols.classes|ids|attrs|vars|mixins|defs` (compiled files skipped, one entry per file, line and role). Paths are `/`-separated and looked up ignoring case (`lower`, `exists`, `file()`).
- **Requests and widgets** (`src/parse/`): `script.js` `ajaxCalls` (jQuery, `.load` on a selection, `$.ajax`, fetch, axios, Angular `http`, XHR; method, `via`, the response's `target` from the call's callbacks and chained `.done`/`.then` only) and `urlOf` (a literal, the literal start of a concatenation or template, `@Url.Action`/`@Url.Content` in an inline script); `razor.js` `calls` (data-url-style attributes, unobtrusive `data-ajax`, htmx, `Ajax.BeginForm`/`ActionLink` with `UpdateTargetId`, `@Url.Action` inside an inline script; a link that is also a call is kept as the call). `widgets.js` `findWidgets(text, { markup, scripts })`: `PLUGINS` (jQuery plugin name → kind and library), `CALLS` and `MARKUP` patterns, a first capture being the target; a view reads markup only (its inline scripts go through `parseScript`). `style.js` also gives `blocks` (top-level, with their line range and the ranges of their rules, classes and ids) and `headers` (`sectionHeaders`). The index adds a `lines` count to each file read, `calls` edges with `{ url, method, via, target }` (`linkScriptRefs`), and `symbols.widgets`.
- **Analysis** (`src/analysis.js`): `pageModel(idx, view)` (cached on the index per build: the render tree, views with `own`, scripts loaded with their import closure, `calls` with `callResult` (action, returned views/partials and what they include, JSON, redirects) and `targetIn`, widgets with `boundTo`, `pageMetrics`), `SCORE` and `WIDGET_WEIGHT` (the README's Complexity section is the spec: change both together), `complexity`, `widgets`, `stylesheets`, `split` (`placeOf` for where a view sits, `prefixOf` for class families), `path` (forward-only search first, then either direction), `graph` (each node at its nearer side), `nodeInfo`, `nodeType`. `renderTree` in queries.js builds the tree (`root`, nodes with `own`), and `treeLines` prints it.
- **Web UI** (`src/web/`): `server.js` (`startUi`, `handler`: 127.0.0.1 only, a `Host` check against DNS rebinding, `routes()` → the JSON API, `source` reads only files the index knows), `page.js` (the one HTML page: CSS tokens with a dark set, a strict CSP), `client.js` (**one function serialised into the page: it may use nothing from outside itself**, and it must survive Bun's minifier, so `test/web.test.js` parses it; DOM only through `h`/`s`/`put`, project text only as text nodes, never `innerHTML`). Views: overview (with the Claude Code setup actions), pages, page (structure, requests, components, assets, score, cascade with inspect, context, screenshots), style guide, changes (with screenshots), audit (dead code, design, repeats with extract, a11y, weight, images, text, models), live, doctor, graph (layered or force layout, pan/zoom, edge-kind filters, path), components, stylesheets (split), selectors, problems, and the source drawer.
- **Tools** (each its own module, each a `{ data, text }` query): `changes.js` (`gitChanges`: git's uncommitted, untracked and `--base` files under the project, `run` stands in for git; `pagesReached`), `context.js` (`context`: candidates in priority order filled into a character budget, `methodRange` for an action's body), `rename.js` (`replaceInQuotes` for markup and scripts, `replaceInSelector` for styles, only on the lines the index lists; warnings for LESS `&` names, run-time names, collisions, built files; `apply` writes), `cascade.js` (`specificity`; the page's stylesheets expanded in import order, not `(reference)` ones; each property's winner by !important, specificity, order), `audit.js` (`deadCode`, `design` with `normalizeColor`, `repeats` (markup lines reduced to their `shape`, windows of `min` lines across views), `a11y` with `A11Y_RULES`, `weight`/`pageWeight`), `diagram.js` (`draw` to Mermaid or DOT; a page, a neighbourhood or a path), `shots.js` (`findChrome`, `capture` over the DevTools protocol with Node's WebSocket, `shot` before/after in `.pilot/shots`, `compareShots`; `baseUrl` remembers the site in `.pilot/config.json`), `png.js` (`decodePng`, `encodePng`, `diffImages`). The style parser also keeps each rule's declarations (`props`: `p`, `v`, `l`, `i` for !important) and `end` line, and `colors`, `zindex`, `important`, `media`; the Razor parser `inlineStyles` and `a11y`.
- **More tools**: `insight.js` (`doctor`: references by kind found/guessed/missing/run time and problems grouped by `pattern`; `models` with `modelName`; `texts`; `images`; `styleguide`), `live.js` (the running site through `shots.js`'s `withPage`/`openBrowser`, one browser for many pages: `inspect` (CDP `CSS.getMatchedStylesForNode`, `servedFile` and `ruleSource` back to the project), `coverage` (`CSS.startRuleUsageTracking` lists used rules only, so `cssRules` reads each sheet for the rest; `usedBytes` for V8's block coverage; state rules skipped), `responsive` (`breakpointWidths`, the `OVERFLOW` script, the viewport meta), `shots` over `pageSet` with `report.html` and `threshold`), `refactor.js` (`splitApply`: blocks with their leading comments into the new files, `unused` imported last, `backup`, `findCompiler` + `compareCss`, rolled back when the CSS changes unless `force`; `extractPartial` with `balance`/`tagDepth`, `isCore` for `<partial>`), `hook.js` (`afterEdit`, `runHook`: Claude Code's PostToolUse JSON in, `hookSpecificOutput.additionalContext` out, nothing when there's nothing to say; `installHook` merges into `.claude/settings.json` with `async: true`), `report.js` (one HTML file, everything escaped, no script). Library stylesheets (vendor CSS) are read for their class names only (`libraryClasses`, symbols with `vendor: true`, line 0), so classes Bootstrap styles count as styled. The UI's actions are `ACTIONS` in `server.js` (POST `/api/action/<name>` with `X-Pilot: 1`; writes refresh the index); `/api/events` streams file changes from a recursive `fs.watch` in `startUi`; `/shots/…` and `/report.html` serve the reports.
- **Queries** (`src/queries.js`): `overview`, `page` (`renderTree`: the outermost layout down, sections placed where rendered; `expandAsset`), `file`, `impact`, `selector`, `styleSymbol`, `find`, `routes`, `problems`, and `resolveTarget` for what a user names. Each returns `{ data, text }`; the text is written for Claude: `path:line`, the most useful first, long lists cut with a count. Keep `--json`'s shapes stable.
- **CLI** (`src/cli.js`): `parseArgs`, `run(argv, { write, error })` → the exit code (null for `mcp`). **MCP** (`src/mcp.js`; `pilot mcp` reads `--root`, else `CLAUDE_PROJECT_DIR`, else the current folder: `mcpRoot` in cli.js, as Claude Code doesn't promise a server's working directory): `TOOLS`, `INSTRUCTIONS`, `createServer({ root, fresh, build })` (the index kept, refreshed before a call when older than `fresh`), `serve`. **Skill** (`src/skill.js`): what `pilot init` writes; `init --mcp` also adds Pilot to the project's `.mcp.json` (`writeMcpJson`, keeping other servers; `mcpServer`: `pilot` in a build, `node <checkout>/bin/pilot.js` from a checkout, `--command` to choose). The README's "Connect to Claude Code" is the setup guide, and the UI's Overview has the same steps (`/api/claude`, `claudeSetup`, `claudeCard`): change them together.

## Tests

`test/fixtures/shop` is a made-up solution with two web projects: `Shop.Web` (MVC 5: BundleConfig, RouteConfig, an Admin area with its own `_ViewStart` and a nested layout, a child action, an editor template, Web Compiler's LESS, a TypeScript file not yet built, a missing partial and a dynamic one) and `Shop.Core` (Core: attribute routes with constraints, a view component, `<partial>`, tsconfig `outDir`, `bundleconfig.json`). `test/parsers.test.js` covers each parser on small inputs; `test/index.test.js` the graph over the fixture (and the cache in a temp copy with `PILOT_CACHE`); `test/queries.test.js` the queries' text and data, the CLI and the MCP handler; `test/analysis.test.js` page models, complexity, widgets, split, path and graph; `test/web.test.js` the server's handler without a socket (the page, the API, the Host check, the source guard; screenshots listed, served by name only, taken only by a POST with `X-Pilot: 1`); `test/tools.test.js` changes, context, rename (applied in a temp copy), cascade, the audits, diagrams and screenshots (a stand-in `capture`, PNGs made in the test). `test/more.test.js` the doctor, models, text, images, style guide, split and extract (applied in temp copies), the hook, the report, the live tools' pure parts (`cssRules`, `usedBytes`, widths, page sets, `shots` with a stand-in) and the UI's actions. Nothing in the suite starts a browser or needs git; the browser tools are checked by hand against a local test site (a small `node:http` server is enough). The fixture's `orders.ts` makes requests (one returning `_OrderRow` into `#orders`), sets up a DataTable and a datepicker, and `Content/everything.less` is the stylesheet to split. Check the UI itself in the pre-installed Chromium (Playwright) after changing `client.js`: `node bin/pilot.js --root test/fixtures/shop ui --no-open`. Tests build with `cache: false` and never touch the user's cache. Paths must work on Windows (CI runs there): use `fileURLToPath`, and compare `/`-separated paths.

## Keeping things in sync

A new query: `src/queries.js`, the CLI's `commands` and `HELP` in `src/cli.js`, `TOOLS` and `INSTRUCTIONS` in `src/mcp.js`, `src/skill.js`, the README's table, and tests. Commit messages are short sentences describing the change, without type prefixes.
