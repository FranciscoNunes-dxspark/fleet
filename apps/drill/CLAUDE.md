# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

A project's tests in the terminal, failures first: Vitest, Jest, `node --test`, Playwright and `dotnet test` (xUnit, NUnit, MSTest), found from package.json, the runners' config files and .NET test projects (or a `drill.json`), each run with its machine reporter to a temporary file and read with a parser pinned to its version; the assertion, a diff of expected and actual and the project's own frames for each failure; the Tree, the flaky tests, the runners' own output through a virtual terminal; `c` for the tests touching what git says changed, `w` to watch; and `drill run` for a pipeline and `fleet mcp`. Drill is a keyboard-driven terminal app built with Ink (React for the terminal) on Node 22+, a sibling of Splice, Bosun, Bilge and the rest. Plain JavaScript ES modules with `.jsx` for components; no TypeScript, no linter config. The README is the user-facing spec; when behaviour changes, update it too.

It lives in the fleet repository, in `apps/drill`, and is built on the fleet's shared kit, `@fleet/kit` (`packages/kit`; the root CLAUDE.md has its rules). Import the kit's files as `@fleet/kit/<file>`; Drill keeps no copy of any of them, and a change to one is a change to every app, so run every app's tests (`npm test` at the root). `src/app.js` tells the kit which app this is (`configureApp`: the name `drill`, the title `Drill`, the version a build bakes in); import `VERSION` and `COMPILED` from it. `src/theme.js` fills the kit's `theme` object with Drill's palette (orange).

## Commands

```bash
npm install                                                    # once, at the repository root: every app and the kit
npm test                                                       # whole suite (node:test), here; npm run test:drill at the root
node --import @fleet/kit/register.js --import ./src/app.js --test test/parsers.test.js   # one file
node --import @fleet/kit/register.js --import ./src/app.js --test --test-name-pattern="TRX" test/*.test.js   # tests matching a name
npm start                                                      # run from the checkout on this folder (needs a real TTY)
npm run demo                                                   # run against the made-up project (needs a real TTY)
node bin/drill.js run --demo                                   # the headless run, on the demo
npm run build                                                  # Bun-compiled executable for this machine → dist/ (the kit's scripts/build.js)
node scripts/logo.js                                           # regenerate assets/ from src/pet.js
```

`--import @fleet/kit/register.js` is required whenever Node loads `.jsx`. The tests also preload `--import ./src/app.js`, so the kit knows the app before any test file loads. CI runs Drill's tests on Linux and Windows whenever `apps/drill` or the kit changes, so paths must work on both (a test's `file` is always `/`-separated and relative to the project). Nothing in the suite runs a test runner, git, an editor or a browser, or reaches the network: the demo and stand-ins for `run` and `fetchImpl` take their place.

Releases are automatic, as every app's: a push to main that changes `apps/drill` (or the kit, `patches/` or the root package files) releases it as `drill-v<version>` (root CLAUDE.md, "Releases"). Compiled builds get the version via `process.env.DRILL_VERSION`.

## Architecture

- **The model** (`src/model.js`, pure): a test is `{ id, runner, file, suite: [titles], name, status: 'failed'|'passed'|'skipped', duration, line?, fqn?, source?, failure?, attachments?, flaky?, from? }` (`makeTest`; `id` is `runner:file:titles › name`, the same from run to run, which the flaky history and re-runs key on; `from` is the suite's id, set by `runSuites`). A failure is `makeFailure({ message, stack, expected?, actual?, root })` → `{ message (cut before the first frame), expected?, actual?, diff: [{ kind: ' '|'-'|'+', text }], stack, frames }`: `expectedActual` reads each library's words (Jest's Expected/Received, Chai's "expected X to be Y", xUnit's Actual, NUnit's But was, MSTest's `Expected:<…>`), `diffInMessage` takes a diff Jest or Vitest already wrote, else `diffLines` (an LCS line diff); `parseFrames` reads V8's, node:test's TAP (no `at`), file URLs and .NET's frames, and `ownFrames` keeps the project's (inside `root`, no `node_modules` or `node:`), relative and `own`, else the first three dimmed.
- **The parsers** (`src/parsers/`, pure): `jestlike.js` (Vitest's and Jest's JSON, one shape: Jest's `failureDetails[].matcherResult` gives expected and actual as values; a file that failed to load is a failed test), `nodetest.js` (`parseTap` for Node 22's TAP: subtests by four-space indent, the YAML block per result by `parseDiagnostics`, suites from `type: 'suite'` or children, files from `location` (Node 22 gives one only to failures and suites: a passing top-level test takes its neighbour's file); `parseSpec` for spec output, the failures matched from its "failing tests:" part), `playwright.js` (suites per file under `config.rootDir`, a test per spec and project, the last try's error and attachments, `flaky` when a retry passed), `trx.js` (`parseXml`, a small reader of elements, attributes, text and CDATA; a test's file is its class, `fqn` Namespace.Class.Method for `--filter`, `source`/`line` from its first own frame). `index.js` **pins them**: `PINS` lists the versions each was checked against (Vitest 1–3, Jest 29–30, Node 22, Playwright 1.40–1.49, TRX), `parserFor(runner, version)` → `{ parse, pin, note }`, a version outside them read as the nearest with a `note` (Playwright past 1.49 quietly). Each pinned version has a fixture in `test/fixtures` (written to the reporters' documented shapes, not captured from a live run); a new version means a new fixture, its test, and the pin.
- **Finding the suites** (`src/detect.js`, pure over `fs`: `read(path)` → text or null, `list(dir)` → `[{ name, dir }]`): package.json files three levels down (`SKIP_DIRS` and hidden folders left out), each's dependencies, scripts and config files, `nodeTestArgs` for a `node --test` script's files, `installedVersion` from `node_modules`, `execFor` (`pnpm exec`, `yarn`, `npx --no`), `playwrightUrl` from its config; .NET test projects by `isTestProject`, one suite each. `readDrillJson` checks `drill.json`, which replaces the detection. A suite is `{ id, runner, cwd, dir, exec, version, url?, target?, args?, command?, from }`.
- **Command lines** (`src/runners.js`, pure): `buildCommand(suite, { tests, files, out, platform })` → `{ command, env, report }`: the runner's reporter for people to the Output view, its machine reporter to `report` in the temporary folder, and what to run (Vitest's and Jest's files and `-t`, node's `--test-name-pattern` and files, Playwright's `file:line`, dotnet's `--filter FullyQualifiedName=` or `~Class.` for changed classes). **Everything put in a command line passes `safeFile`, `safeArg`, `namePattern` (a name becomes letters, digits and a few marks, `.` for the rest) or `safeFqn`, and `quote` for the platform's shell**: keep that for anything new.
- **The provider** (`src/provider.js`): `createDrill({ run, fetchImpl, home, fs })`: `detect(root)`, `runSuite(suite, { root, tests, files, signal, onData })` (a `mkdtemp` folder removed after; the kit's `run` with `onLine` into `onData`; a failing exit still reads the report; no report → `{ ran: false, error }` from the runner's last lines; node's version asked of `node --version` once), `appUp(url)`, `changed(root)` (`git rev-parse --show-prefix`, `git status --porcelain=v1 -uall`), `testFiles(root)`, `watch(root, onChange, { ignore })` (`fs.watch` recursive, debounced), `launch(command)` (an editor, the trace viewer: `run` without waiting), `shell`, `exists`, `loadHistory`/`saveHistory`, `writeFile`. `src/demo.js` `demoDrill()` has the same interface (`state.calls`, `state.launched`, `state.appUp`, `state.fixed`, `state.changed`, `state.watch` to fire a change, `state.runs` for the flaky test that fails only on its first run); a new operation needs both, and its test.
- **A run** (`src/session.js`): `runSuites(provider, { root, suites, tests, filesBySuite, signal, onData, onSuite, moods })` runs the suites in `ordered` order (unit, .NET, then Playwright), skipping a suite nothing picked is in; **before Playwright it asks `appUp(suite.url)` and doesn't run it when nothing answers** (`e2e.js` `appDown` says so with Bosun's mood, from the family's `readMoods`: Bosun keeps its crew to itself, so this is the reading path). `mergeTests` puts a re-run's tests in place; `filesBySuiteOf` gives test files to suites (the one that ran it, else by place and name; C# files as `classesIn`'s classes). `drill run` and the app both go through it.
- **Changed files** (`src/changed.js`, pure): `parsePorcelain`, `isTestFile`, `stem`, `importsOf`, `testsTouching(changed, testFiles)` → `[{ path, why }]` (the file itself, matching names, an import of it, a C# class used), `classesIn`.
- **Flaky** (`src/flaky.js`): `recordRun(history, tests)` (passed `p`, failed `f`, retried into a pass `r`; thirty runs kept; each id's runner, file, suite, name, line, fqn beside them), `flakyTests(history)` (both passed and failed in their last ten), `historyFile(root)` (`<DRILL_HOME>/history/<sha1 of the path, lower-cased on Windows>.json`).
- **The editor and the trace** (`src/editor.js`, pure): `editorSetting(config)` (the setting, `DRILL_EDITOR`, `VISUAL`, `EDITOR`), `editorCommand(editor, file, line, { column })` → `{ command, terminal }` per editor family; `actions.openFrame` launches it through the provider (the kit's `run.js`), or copies a terminal editor's command. `actions.showTrace` launches `<exec> playwright show-trace <trace.zip>`.
- **`src/actions.js`**: every user-facing operation, written once (`load`, `runAll`, `runFailed`, `runTests`, `runChanged`, `toggleWatch`, `openFrame`, `showTrace`, `share`, `take`, `runners`, `runCommand`…); keys and slash commands call these with `ctx`. `runWith` is the one path a run takes: the Output view reset, `runSuites` inside a `task`, the tests merged into `ctx.run`, the history recorded and saved, a note for each suite that couldn't run, the activity line.
- **`src/commands.js`**, **`src/help.js`**: the slash-command table and completion; the `?` window's sections. **`src/headless.js`**: `HEADLESS` (`run`, `list`), `parseArgs`, `failureJson`, `runHeadless(args, { provider, write })` → the exit code (0 passed, 1 failed as `--fail-on` counts, 2 couldn't run), which `cli.jsx` runs before asking for a terminal. **Keep `drill run --json`'s shape**: `fleet mcp` reads it.
- **`src/ui/App.jsx`**: layout, focus, the prompt, overlays, the activity lines and **`ctx`** (read the `Object.assign(ctx, {...})` block before adding an action): `provider`, `data` (detect's), `run` (`{ tests, results, counts, at }`), `history`, `env` (getters), `cwd()`, `moveTo`, `setData`, `setRun`, `setHistory`, `watching()`/`setWatching(stop)`, `isBusy()`, `task`, `note`, `progress`, `output` (`reset(title)`, `write(text)`: the Output view's `VirtualTerminal` from `@fleet/kit/vt.js`, 5000 lines of scrollback, redrawn at most every 100 ms), `view()`/`setView`, `showFailure(test)`, `copy`, `showText`. The global keys are `ctrl+r`, `R` (alt+r: the kit's keymap makes uppercase shortcuts alt+letter), `c`, `w`; views take `r`, `t`, `y`, `o`, `f`.
- **`src/ui/*View.jsx`**: Failures (the list and the failure under it, `failureRows`; inside it the cursor walks frames and attachments), Tree (`src/tree.js` `treeRows`, pure), Flaky, Output (`outputLines` over the virtual terminal), Log. Views must check `ctx.viewHasKeys()` at the start of their `useInput` handlers; `useListNav` from the kit is the cursor. `Viewer.jsx` shows text over the view, with the kit's search.
- **The family** (`@fleet/kit/family.js`, shared and never edited here; `src/share.js`, `src/moods.js`, pure): Drill is in `FAMILY` (role `TESTS`, Peck). `t` hands Splice a `test` context (`testContext`: file and the line it broke at, `placeOf`; name; the message's first line; the runner), through `copiedNote`. It takes a `test` context (`findTest`, else the file through `filesBySuiteOf`); any other, `/take` says whose it is. Runs go to the activity log with the project (counts only); `submit` in App calls `recordCommand('drill', line)`; Peck's mood to `writeMood`; tests point `FAMILY_HOME` at a temp folder (`tempHome`). `/env` is the kit's `environments.js`.
- **Config** (`src/config.js`): `~/.drill/config.json`, overridable with `DRILL_HOME` (the history lives there too). Change it only through `ctx.setConfig`.
- **Updates, hosted mode, mouse, theme and text**: as Bilge's: `appTerminal()` in `cli.jsx`, the update only in compiled builds and never hosted, `useMouse` in views, colours read from `theme` while drawing, `@fleet/kit/text.js` for widths.
- **Peck** (`src/pet.js`, `src/ui/Pet.jsx`): the woodpecker's pixel art and mood. `assets/` is generated from it by `scripts/logo.js`; don't hand-edit those files.

## Tests

`test/app.test.js` and `test/family.test.js` are end-to-end: `<App>` over `demoDrill()` with `ink-testing-library`, typing keys and asserting on `lastFrame()` and `provider.state` (the Output view's rows are the virtual terminal's, with colour codes: compare them through `stripAnsi`). `test/parsers.test.js` reads every fixture in `test/fixtures` (one per pinned version: Vitest 1–3, Jest 29–30, Node 22's TAP and spec, Playwright 1.4x, xUnit's, NUnit's and MSTest's TRX) and covers the pins; `test/runners.test.js` detection over an in-memory file system, the command lines and their quoting, changed files, the flaky history, the editor, the app's check and the provider over a stand-in `run`; `test/headless.test.js` `drill run` and `drill list` over the demo. Use `until(check, what)` to wait for frames rather than fixed sleeps.

## Keeping things in sync

Adding or changing a key or command touches several places: the handler (view or `App.jsx`), `src/commands.js` for slash commands, the `?` window's sections in `src/help.js`, the footer `HINTS` in `App.jsx`, and the tables in `README.md`. Commit messages are short sentences describing the change, without type prefixes.
