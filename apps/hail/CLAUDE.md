# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

An HTTP client for the terminal, over .http files. Hail is a keyboard-driven terminal app built with Ink (React for the terminal) on Node 22+. It was started from slipway, and it's a sibling of Splice (a git client) and Trawl (a SQL client). Plain JavaScript ES modules with `.jsx` for components; no TypeScript, no linter config. The README is the user-facing spec; when behaviour changes, update it too.

It lives in the fleet repository, in `apps/hail`, and is built on the fleet's shared kit, `@fleet/kit` (`packages/kit`; the root CLAUDE.md has its rules): `text.js`, `ui/parts.jsx`, `ui/hooks.js`, `ui/HelpView.jsx`, `ui/Palette.jsx`, `mouse.js`, `selection.js`, `clipboard.js`, `jsx-hooks.js`, `register.js`, `help-layout.js`, `keymap.js`, `usercommands.js`, `palette.js`, `run.js`, `credentials.js`, `claude-cli.js`, `family.js`, `update.js`, `theme.js` and the build, the kit's `scripts/build.js`. Import them as `@fleet/kit/<file>`; Hail keeps no copy of any of them, and a change to one is a change to every app, so run every app's tests (`npm test` at the root). Anything only Hail needs lives in its own file (Hail's `search.js`). `src/app.js` tells the kit which app this is (`configureApp`: the name `hail`, the title `Hail`, the version a build bakes in); import `VERSION` and `COMPILED` from it. `src/theme.js` fills the kit's `theme` object with Hail's palette.

## Commands

```bash
npm install                                                    # once, at the repository root: every app and the kit
npm test                                                       # whole suite (node:test), here; npm run test:hail at the root
node --import @fleet/kit/register.js --import ./src/app.js --test test/units.test.js      # one file
node --import @fleet/kit/register.js --import ./src/app.js --test --test-name-pattern="settings" test/*.test.js   # tests matching a name
npm start                                                      # run from the checkout (needs a real TTY)
npm run build                                                  # Bun-compiled executable for this machine → dist/ (the kit's scripts/build.js)
node scripts/logo.js                                           # regenerate assets/ from src/pet.js
```

`--import @fleet/kit/register.js` is required whenever Node loads `.jsx`: it installs a module hook (the kit's `jsx-hooks.js`) that compiles `.jsx` with esbuild on import. There is no dev build step. The tests also preload `--import ./src/app.js`, so the kit knows the app before any test file loads. CI runs Hail's tests on Linux and Windows whenever `apps/hail` or the kit changes, so path handling and line endings must work on both (`.gitattributes` forces LF).

The Ink patch is the repository's (`patches/ink+6.8.0.patch` at the root, applied by `npm install` there); the root CLAUDE.md says what it does, and the kit's `test/ink-patch.test.js` checks it.

Releases are automatic: every push to main that changes `apps/hail` (or the kit, `patches/` or the root package files; not Markdown-only ones) releases Hail from the root Release workflow as `hail-v<version>`: the newest `hail-v…` release with the patch raised, or `package.json`'s version when that's higher (bump it there for minor or major). It sets the version in the runner before building and commits nothing back, so `package.json` on main lags behind the releases. Compiled builds get the version via `process.env.HAIL_VERSION` (defined by the kit's `scripts/build.js`, and written out in `src/app.js`), which also sets `COMPILED`; from a checkout `src/app.js` reads `package.json`, and the update check is skipped.

## Architecture

- **`src/http-file.js`**: parsing `.http` files (VS Code's REST Client and JetBrains' HTTP Client format) into `{ variables, requests }`, pure. A request's `label` (its name, else method and URL) is how responses are kept.
- **`src/variables.js`**: filling in `{{...}}`, pure apart from the built-ins, whose clock, randomness, process environment and `$azToken` come in through `env` so tests fix them. The environment wins over the file's `@variables`; `name.response.body.path` reads earlier responses by request name.
- **`src/environments.js`**: `http-client.env.json` and `http-client.private.env.json` beside the file, `$shared` in each.
- **`src/send.js`**: `prepare` (variables filled in, a body file read), `send` (through `fetch`, which App doesn't stub: tests run a server on 127.0.0.1), `networkError` (fetch's "fetch failed" in words), `prettyBody`, `toCurl`.
- **`src/files.js`**: `loadHttpFile` (what `App`'s `load` prop defaults to: the parsed file and its environments), finding `.http` files, and `/new`'s example. `App` watches the file's folder and reloads when it or an env file changes.
- **`@fleet/kit/credentials.js`**: Trawl's credential store with Hail's names (Credential Manager through PowerShell, `security`, `secret-tool`; secrets on stdin, never argv except macOS). `{{$secret name}}` reads it; `actions.js` `prepared` asks for a missing one (`ctx.askSecret`, the masked `SecretPrompt` from `parts.jsx`) and saves it. The config keeps the names only. App takes it as the `credentials` prop; tests pass `memoryCredentials()`.
- **`src/history.js`**: every response, one JSON line, in `~/.hail/history/<hash of the file's path>.jsonl`. `entryFor` blanks the secret values `prepare` reports in `secrets` (from `$secret` and `$azToken`) everywhere and hides credential headers, so nothing secret reaches the disk; keep it that way for anything new that's filled in from a secret. `App` restores the latest response per request label when a file opens. `src/diff.js` compares two for History's `d`.
- **Response handlers and running the file** (`src/checks.js`, `src/runner.js`, `src/headless.js`): `checks.js` `runChecks` runs JetBrains' `> {% %}` scripts in a `node:vm` context of their own (`DONT_CONTEXTIFY`, a time limit); only a JSON string goes in and one comes out, so no object of this process reaches a script. Keep it that way. `runner.js` `exchange` sends a prepared request and runs its handlers; its report is pure and shared by `/send all` (`actions.js` `sendAll`) and `hail test` (`headless.js`, run from `cli.jsx` before the TTY check). Globals set by scripts live in App (`ctx.globals()`), per file, in memory only, and win over the environment in `fill`.
- **The wire** (`src/send.js`, `src/transport.js`, `src/cookies.js`, `src/bodies.js`): `send` follows redirects itself (`redirect: 'manual'`), so the per-file-and-environment cookie jar (`ctx.cookieJar()`, memory only) sees every hop; `# @no-redirect`, `# @no-cookie-jar` and `# @timeout` are a request's `options` (directives parsed in `http-file.js`). `transport.js` adds a dispatcher (undici's Agent, taken from fetch's own global dispatcher, never a dependency) for an environment's `SSLConfiguration` and for `HTTPS_PROXY`/`HTTP_PROXY` (a CONNECT tunnel; loopback and `NO_PROXY` go straight), or Bun's `tls`/`proxy` options in the compiled builds. `bodies.js` turns multipart bodies (files as `< path` lines) into bytes (`payload`; `body` stays the text kept in history) and GraphQL into `{ query, variables }`. `>> path` saves the raw body (`runner.js` `saveBody`). `src/curl.js` reads curl command lines for `/import-curl`, pure.
- **Contract drift** (`src/contract.js`, `src/yaml.js`, both pure but `loadContract`): `/contract` keeps an OpenAPI 3 or Swagger 2 document per file in the config (`contracts`); App reads it on open and on `r` (`ctx.contract()`), and `ctx.contractFor(sent)` checks a response once (a WeakMap per document), so restored history entries are checked too. Nothing about it is kept in the history. `runner.js`'s report lists drift (`contract` on a result) and fails on it only with `strict` (`hail test --contract-strict`). `yaml.js` reads the block and flow YAML that OpenAPI documents use, no more.
- **`/load`** (`src/load.js`): `runLoad` sends through `send.js`'s `send` with the request filled in once, no cookie jar, handlers, `>>` or history; `ctx.setBusyLabel` is its progress. The stats and report are pure. Limits: 5,000 requests, 100 at a time.
- **The family** (`@fleet/kit/family.js`, shared and never edited here; `src/takes.js`, Hail's, pure): `/take` (`actions.js` `take`, also a context pasted bare) replays a `request` (`### replay …`, appended through `ctx.appendRequests`), makes `rows` a body (`ctx.replaceRequestBody`, through the editor so ctrl+z undoes it), and finds a `logline`'s request id in the history's headers (`ctx.showHistoryEntry`). `/family` (`familyOffers`) copies command lines for Splice, Bosun and Trawl, never a password. A paste of a command or context while a view has the keys opens the prompt with it (in `useKeyTranslation`'s translate, before your keys). Hoot's mood goes to `writeMood('hail')` when it changes (`pet.js` `familyMood`; a task can resolve with `worried` for a response whose checks failed) and `readMoods` runs every `familyEvery` ms (a prop, 30 s); tests' `tempHome` sets `FAMILY_HOME`.
- **`src/claude.js`**: `/draft` through `claude -p`, run by the family's shared `claude-cli.js` (no MCP, no settings, no tools). `draftPrompt` and `parseDraft` are pure; App takes `ask` as the `askClaude` prop from `cli.jsx`, and tests stub it.
- **Data viewer** (`@fleet/kit/datatree.js`, `@fleet/kit/ui/DataViewer.jsx`): `d` and `/data` in Response open the body as a tree (JSON, JSON lines) or a table (CSV, TSV, arrays of objects) when it parses as one; `actions.js` `showData` decides, and the viewer is an overlay like the text viewer. The parsing and path query are the kit's, pure and tested there.
- **`@fleet/kit/search.js`**: the viewer search (`matcher`, `markRanges`), for the Response view's `/`. A view that takes keys the app would otherwise use sets `ctx.claimsKey(input, key)`; App's dispatcher skips its own keys when it returns true (the Response view clears it when it unmounts).
- **`src/azure.js`**: `{{$azToken}}` through the Azure CLI, as Trawl and Keel get tokens; App takes it as the `azToken` prop.
- **`@fleet/kit/run.js`**: the only place another program is started. Nothing it starts has a terminal, so nothing may wait on a prompt; an abort kills the whole tree (`taskkill /T` on Windows). Its `callSignal(signal)` gives one call (a fetch) a signal of its own under a long-lived one, tied to it only until `done()`, so many calls leave no listeners piled on it.
- **`src/actions.js`**: every user-facing operation, written once. Keys and slash commands call these with `ctx`. Questions before anything destructive live here (`ctx.confirm({ ..., danger: true })`).
- **`src/commands.js`**: the slash-command table (`name`, `args`, `desc`, optional `complete`, `run(ctx, rest)`) and completion. Args in `[brackets]` are optional, so picking the command runs it at once.
- **`src/ui/App.jsx`**: layout, focus, the prompt, overlays, the activity log and **`ctx`**: a stable object exposing `data` and `config` (getters), `task` (a visible, cancellable job with the spinner), `note`, `confirm`, `prefill`, `showText`, `showPicker`, `copy`, `setConfig`. Read the `Object.assign(ctx, {...})` block before adding an action.
- **`src/ui/*View.jsx`**: one component per tab: Requests (the list, and beside it the request or its response, drawn by `ui/response.js`), Response (the whole width, with search), History (the kept responses), Log. Views must check `ctx.viewHasKeys()` (or `ctx.overlayHasKeys()` in overlays) at the start of their `useInput` handlers. `useListNav` in `@fleet/kit/ui/hooks.js` is the shared cursor and scroll logic.
- **Mouse** (`@fleet/kit/mouse.js`, `@fleet/kit/selection.js`; `apps/splice/docs/mouse.md` has the design): `terminalMouse` strips mouse reports out of stdin before Ink sees them and hands them to `App` as the `mouse` prop; tests pass a fake (`test/clicks.test.js`). Components register with `useMouse(ctx, handler)`; a view's rows start one line under its panel's top border. Views name their `useInput` handler `keys` so a double-click can call `keys('', { return: true })`.
- **Updates** (`@fleet/kit/update.js`): once a day, the newest `hail-v…` release of the fleet repository, from GitHub's releases API, then `gh api` while the repository is private. A newer release is installed in the background next to the executable, checked against `SHA256SUMS.txt`. Release file names must match `buildTargets` in the kit's `update.js` (the kit's `scripts/build.js` builds those). `cli.jsx` passes `checkUpdate` and `installUpdate` only in compiled builds.
- **Notifications** (`src/notify.js`, Trawl's): `App`'s `task` calls the `notify` prop (cli.jsx writes a bell and OSC 9 / OSC 777) when a run that wasn't cancelled took over `notifyAfter` seconds (10). The `notify` setting turns it off; tests pass a recorder or nothing.
- **Config** (`src/config.js`): `~/.hail/config.json`, overridable with `HAIL_HOME` (tests use it). Change it only through `ctx.setConfig`: `App` saves its whole copy. A new setting is a row in `src/settings.js` plus the README's Settings section.
- **Theme and text**: `src/theme.js` has a dark and a light palette (`DARK`, `LIGHT`, the methods' colours in each); `applyTheme(config)` copies one into `theme` (the Theme setting, `auto` reading `COLORFGBG`) and the accent over it, at start-up in `cli.jsx` and from Settings, as in Splice. Every colour comes from `theme` and is read while drawing: a module-level table of colours uses getters or a function (`COLORS()` in `EditView.jsx`, `methodColour`), never values copied at import. Use `BULLET` instead of `⏺`, and `@fleet/kit/text.js` (`fit`, `wrap`, `stringWidth`) for width-aware truncation, never `.length`.
- **Hoot** (`src/pet.js`, `src/ui/Pet.jsx`): the mascot's pixel art and mood. `assets/` is generated from it by `scripts/logo.js`; don't hand-edit those files.

## Tests

`test/app.test.js` and `test/clicks.test.js` are end-to-end: they write a `.http` file into a temporary folder, start an HTTP server on 127.0.0.1, render `<App>` with `ink-testing-library`, type keys into stdin and assert on `lastFrame()`; nothing reaches the internet. `test/http.test.js` covers the format, variables, environments and sending; `test/keeping.test.js` secrets, history, diffs and drafts; `test/features.test.js` drives those through the UI. Use `until(check, what)` from `test/helpers.js` to wait for frames rather than fixed sleeps. `test/units.test.js` covers commands, help, settings, the pet and the updater.

## Keeping things in sync

Adding or changing a key or command touches several places: the handler (view or `App.jsx`), `src/commands.js` for slash commands, the `?` window's sections in `src/help.js`, and the tables in `README.md`. Commit messages are short sentences describing the change, without type prefixes.
